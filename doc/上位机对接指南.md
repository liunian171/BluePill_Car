## 1. 链路准备

下位机有**两条并列链路**，跑**同一套协议**（换链路不改代码）。**USB 主链是推荐选择**：

| 项 | **USB CDC（主链，推荐）** | BT04 蓝牙 SPP（备链） |
|----|------------------------|---------------------|
| 物理接口 | USB 虚拟串口（`VID:PID = 0483:5740`） | 经典蓝牙 SPP，配对 PIN `1234`，透传无封装 |
| 串口参数 | 波特率不适用（USB FS bulk） | **9600-8N1**（改波特率须固件与模块同步改） |
| 端口（上位机侧） | 枚举出的 COM 口（一次拔插后稳定） | 虚拟 COM 口，**端口号随配对漂移**（历史 COM15→14→12） |
| 打开耗时 | 即时 | 首次 open 可能**阻塞 20s+**（微软栈建链属正常）→ 超时设 ≥90s |
| 单连接限制 | 无 | BT04 只允许一个客户端（手机 APP 占着就连不上） |
| 判活依据 | 打开端口即拉 DTR；发 `PING` 得 `PONG` | 同左（复位后会先收到 `UART2 Ready` 横幅，**但横幅不是判活依据**） |

- 端口自动发现（两条链路一起扫、自动归类、报 owner）：`python tools/link_probe.py`
- 烧录新固件后 **USB 需要拔插一次**（F103 软复位不重枚举，打开端口会报"错误 31"）→ 用 `python tools/flash_flow.py --flash` 自动等待+验证

## 2. 接入生命周期（五步，缺一不可）

1. **打开串口** → 复位一次小车 → 读判活：USB 链路直接 `PING`；BT04 链路会先看到 `UART2 Ready` 横幅
2. **判活**：发 `PING`，收到 `PONG` 才算固件运行正常（⚠️ 横幅不能当判据——init 失败时横幅照样发但永远无应答）
3. **取指挥权**（双链路必做）：发 `LINK ?` 查当前 owner；**不是自己就发 `LINK USB`（或 `LINK UART`）**。
   ⚠️ **非 owner 链路的命令会被拒**：文本回 `BUSY:<owner>`、二进制帧同（仅心跳 `0xF0` 放行）——
   把 `BUSY` 当故障是最常见的误判来源；`STOP` 与 `LINK ?` 不受门控，任何链路直达
4. **发命令必须读应答**：每条被识别的命令必回一行文本（如 `M0 60` → `M0:60RPM`），**读到对应应答才算执行**；未识别命令/帧回 `?`
5. **开启看门狗**：发 `WD 500`——之后 500ms 内 **owner 链路**无下行字节 → 车自动急停（断链兜底）；**保活 = 周期发任意字节**（建议 200ms 一次 `PING` 或心跳帧 `0xF0`）；`STOP` 或任意字节可解除闩锁
6. **急停兜底**：任何时候 `STOP`（双轮刹停 + 舵机回直行 + 关所有工具链；**不受指挥权限制**）

> 上位机读串口时**不要假设"下一行就是自己命令的应答"**——随时可能插入异步行：
> `USB LOST -> UART TAKEOVER`（USB 失联自动切 UART）、`USB READY`（USB 恢复，owner 不变）、
> `WD TIMEOUT STOP`（看门狗急停）。建议按行前缀分类解析。

## 3. 下行①：文本命令速查（30 条）

行尾 `\n` 或 `\r\n` 均可；单行 ≤19 字符；大小写敏感。

| 组 | 命令 | 说明 |
|----|------|------|
| 链路 | `PING` / `STOP` | 心跳 / **急停**（双轮刹停+关巡线+舵机回正+关工具链；**不受指挥权门控**） |
| 链路 | `LINK` / `LINK USB` / `LINK UART` | 查指挥权（回 `OWNER:USB|UART`）/ 切换（接管/让出/抢回三语义合一）；调参会话中回 `BUSY:SESSION`；目标链路被编译期关闭回 `LINK:OFF` |
| 电机 | `M0 <rpm>` `M1 <rpm>` `MS <rpm>` | 单轮/双轮目标转速（带符号 RPM；**手动指令会取出巡线接管权**） |
| 电机 | `B0` / `B1` | 单轮刹车（清目标+释放 PID+物理刹停） |
| PID | `P<id> <kp100> <ki100> <kd100>` | 单电机增益（×100 整数，如 `P0 87 40 0`） |
| PID | `<kp100> <ki100> <kd100>` / `S` | 双电机增益 / 交换两侧增益（回显真值可当读回用） |
| 前馈 | `FF <val100>` | 速度环前馈 ×100（辨识值 ≈100 即 1.0） |
| 舵机 | `SV <deg>` / `SV+` / `SV-` | 输出域绝对角，**直行 = −90**，限位 [−115, −65] |
| 舵机 | `SL/SR/SC <deg>` | 左限/右限/直行位标定（RAM 生效） |
| 编码器 | `E<id> <ppr>` | 设 PPR（RAM 生效；当前 1466） |
| 巡线 | `L/LA 0/1`、`GK/GD/GS <f>`、`GI`、`GC/GT <int>` | ⚠️ 当前固件巡线已剔除：命令可发、应答正常，但**全部 no-op**（真伪看 OLED 页 7 `LINE:OFF`） |
| 调参 | `TEL 0/1`、`STEP <id> <u> <t> [div]`、`REC 0/1`、`DUMP` | 遥测/阶跃/机内记录（见 §5） |
| 上位机 | `ODOM 0/1`、`WD <ms>` | 位姿帧开关 / 看门狗 |
| IMU | `ITEL 0/1/2`、`IGAIN <kp> <ki>`、`IDRIFT 0/1`、`IRATE <ms>`、`ICAL` | IMU 遥测/增益/漂移开关/节拍/重校准 |

## 4. 下行②：二进制帧（程序化控制推荐）

```
0xAA | CMD(1B) | 参数区(IEEE-754 f32, 小端) | 0xFF 0xFF
```
- 帧尾 `FF FF` 结束本帧；帧内允许出现 `0xAA`（不重同步）
- **100ms 帧超时重同步**：蓝牙吞帧尾后固件自动丢弃半帧重来——上位机无需重传逻辑，但**一帧字节应连续发送**

| CMD | 参数区 | 帧长 | 含义 | 应答 |
|:---:|--------|:---:|------|------|
| `0x01` | id(1) + float(4) | 9 | 电机转速（带符号 RPM） | `M<id>:<rpm>RPM` |
| `0x02` | id(1) + float(4) | 9 | 电机线速度 m/s | `M<id>:<cm/s>cm/s` |
| `0x03` | id(1) | 5 | 单轮刹车 | `M<id>:BRAKE` |
| `0x10` | 0x00(1) + float(4) | 9 | 舵机角（直行 −90） | `SV:<deg>` |
| `0x20` | id(1) + float(4) | 9 | 开环占空比 %（−100~100） | `D<id>:<pct>.<1位小数>`；越限回 `?` |
| `0xE0` | id(1) + float×3 | 17 | PID 增益 | `OK` |
| `0xF0` | — | 4 | 心跳（**唯一在非 owner 链路也放行的帧**） | `PONG` |

### 5.1 命令应答（每命令必回，执行确认唯一依据）

| 触发 | 应答 | 示例 |
|------|------|------|
| `PING` / 帧 `0xF0` | `PONG` | |
| `STOP` | `STOP OK LINE OFF` | |
| `M0/M1/MS <rpm>` | `M<id>:<rpm>RPM` | `M0:60RPM` |
| `B0/B1` / 帧 `0x03` | `M<id>:BRAKE` | |
| `P<id> …` | `PID<id>:<kp100> <ki100> <kd100>` | `PID0:87 40 0` |
| `S` | `SWAP:M0 <kp> <ki> <kd>  M1 <kp> <ki> <kd>` | ×100 整数 |
| `L 0/1` / `LA 0/1` | `LINE:<0/1>` / `LA:<0/1>` | ⚠️ 巡线剔除态下仍回显但 no-op |
| `GK/GD/GS <f>` | `GK:<int>.<dec1>` 等 | **回显输入值**（非内部真值） |
| `SV <deg>` 等 | `SV:<角>.<dec1>` | `SV:-90.0`；入参越限尾部加 ` BAD` |
| `STEP …` | `STEP GO <id> <u> <t> <div>` / `STEP END` / `STEP BAD|BUSY` | |
| `TEL/REC 0/1` | `TEL:<0/1>` / `REC:<0/1>` | |
| `DUMP` | `DUMP <n>` + n 行数据 + `DUMP END` | |
| `ODOM 0/1` | `ODOM:<0/1>` | |
| `WD <ms>` | `WD:<ms>`（越限 `WD BAD`） | |
| `ITEL/IGAIN/IDRIFT/IRATE/ICAL` | `ITEL:<m>` / `IGAIN:<kp> <ki>` / `IDRIFT:<0/1>` / `IRATE:<ms>` / `ICAL:GO` | |
| `LINK ?` / `LINK <目标>` | `OWNER:USB|UART` / `LINK:<目标> OK` | 指挥权查询 / 切换；`BUSY:SESSION`（会话锁）、`LINK:OFF`（链路被编译期关闭） |
| **非 owner 链路**的命令 | `BUSY:USB` / `BUSY:UART` | 门控拒绝（`STOP`、`LINK ?` 除外） |
| 未识别 | `?` | |

> 浮点应答仅 0.1 精度（固件禁 `%f`，十分位饱和在 9 不进位）；高精度读数用二进制帧或 `REC/DUMP`。

### 5.2 遥测 CSV（按需开启，行文本）

| 开关 | 格式 | 频率 |
|------|------|------|
| `TEL 1` | `tick,tgt0,rpm0,tgt1,rpm1` | 10 Hz |
| `STEP`（自动开） | `t_ms,rate_0E3,rpm_x10` | 20 Hz（`div=2` 降 10Hz） |
| `REC 1` → `DUMP` | 同 STEP 格式，机内 128 条缓冲后重放 | 20 Hz 记录 |
| `ITEL 1` | `tick,gx10,gy10,gz10,roll10,pitch10,yaw10,stable,driftz100` | 5 Hz（随 IRATE） |

### 5.3 位姿帧（上位机 odometry 数据源，`ODOM 1` 开启 / `ODOM 0`、`STOP` 关闭）

帧体系同下行（`0xAA` + CMD + 小端参数区 + `FF FF`，**无校验**——坐标权威在上位机）：

| CMD | 参数区 | 帧长 | 频率 | 含义 |
|:---:|--------|:---:|:---:|------|
| `0x51` ODOM | ΔX(f32) + ΔY(f32) + Δθ(f32) + ts_ms(u32) | **20** | **20 Hz** | 车体系**增量位姿** |
| `0x52` ATT | roll(f32) + pitch(f32) + yaw(f32) + ts_ms(u32) | 20 | 10 Hz | 欧拉角透传（°） |

**坐标域（解析前必读）**：
- `ΔX`：mm，**车头正前为正**（中点积分 ΔX = Δs·cos(Δθ/2)）
- `ΔY`：mm，**车体左侧为正**
- `Δθ`：°，**逆时针为正**，归一 (−180, 180]；主路径 = IMU yaw 差分（打滑不误）
- `ts_ms`：下位机毫秒计数（HAL_GetTick），供帧对齐

**世界系轨迹重建**：`θ += Δθ; x += ΔX·cos(θ−Δθ/2); y += ΔY·sin(θ−Δθ/2)`（角度转弧度）。

## 6. 带宽与丢行（对接前必知）

**走 USB 主链时下表基本不适用**（实测单命令往返 0.2ms、`ODOM 1` 20Hz + ATT 10Hz 连续 10s 零丢帧、突发 40 条命令零丢）。以下约束针对 **BT04 备链**：

| 项 | 值 | 应对 |
|----|-----|------|
| 总预算 | 9600 bps = **960 B/s** | — |
| `TEL 1` | ≈20% ✅ | 可常开 |
| ODOM+ATT 全开 | ≈**62%** ⚠️ 且阻塞发送（每帧 ~21ms） | 仅对接/调试会话开；要 50Hz 或并行遥测**必须先提速 115200**（固件+对端同步改）；ROS 下位机模式建议改走 USB |
| BT04 打包节拍 | **≈15.5ms**（真凶，非带宽） | 命令往返延迟量化到 15.5ms 整数倍；高行速率成块丢行 → 降频或 `REC+DUMP` |
| ack 阻塞 | 6–11 ms/条 | 勿高频连发命令 |
| 单次突发下行 | **≤239 B**（≈47 条文本命令） | 超限**丢新字节**（已收数据不受影响）；溢出计数可在 OLED 页 7 `O<n>` 查（两条链路共用） |

## 7. 已知限制

- **非 owner 链路的命令被拒**（`BUSY:<owner>`）→ 先 `LINK ?` 查 owner，必要时 `LINK USB` / `LINK UART`；`STOP`/`LINK ?` 不受限
- **USB 烧录后需拔插一次**（软复位不重枚举，端口打不开报"错误 31"）→ `tools/flash_flow.py` 自动化
- **无 CRC**：帧尾 `FF FF` 截帧概率极低 + 100ms 超时重同步兜底；重要参数下发后读回确认
- **巡线已剔除**：`L/LA/GK/GD/GS/GI/GC/GT` 均为 no-op（固件侧 `car_config.h` 开关）
- `M0 60` 这类手动命令会退出巡线接管（设计如此；当前固件巡线本就不在）
- 角度文本应答仅一位小数

## 8. Python 参考实现（可直接抄）

```python
import struct, serial, threading, time

class BluePillLink:
    def __init__(self, port, baud=9600):
        # open 可能阻塞 20s+（微软栈建链），timeout 给足
        self.ser = serial.Serial(port, baud, timeout=0.3, write_timeout=2)

    # ---- 文本命令：发 + 等应答（确认制）----
    def cmd(self, text, expect=None, retries=3):
        for _ in range(retries):
            self.ser.reset_input_buffer()
            self.ser.write((text + "\n").encode())
            deadline = time.time() + 1.0
            buf = b""
            while time.time() < deadline:
                buf += self.ser.read(64)
                line = buf.decode(errors="ignore")
                if expect is None or expect in line:
                    return line.strip()
            # BT04 打包节拍 ~15.5ms，偶发延迟重试一次即可
        raise TimeoutError(f"no ack for {text!r}")

    # ---- 二进制帧 ----
    @staticmethod
    def frame(cmd: int, payload: bytes = b""):
        return bytes([0xAA, cmd]) + payload + b"\xFF\xFF"

    def motor_rpm(self, motor_id: int, rpm: float):
        self.ser.write(self.frame(0x01, bytes([motor_id]) + struct.pack("<f", rpm)))
        return self.ser.readline().decode(errors="ignore").strip()   # 'M0:60RPM'

    def servo_deg(self, deg: float):   # 直行 = -90
        self.ser.write(self.frame(0x10, b"\x00" + struct.pack("<f", deg)))
        return self.ser.readline().decode(errors="ignore").strip()

    # ---- ODOM/ATT 帧解析（ODOM 1 开启后）----
    def odom_frames(self):
        """生成器: yield ('ODOM', dx, dy, dtheta, ts) / ('ATT', r, p, y, ts)"""
        buf = b""
        while True:
            buf += self.ser.read(128)
            while True:
                i = buf.find(b"\xAA")
                if i < 0 or len(buf) - i < 20:
                    buf = buf[i:] if i >= 0 else b""
                    break
                cmd = buf[i+1]
                body, tail = buf[i+2:i+18], buf[i+18:i+20]
                if tail != b"\xFF\xFF" or cmd not in (0x51, 0x52):
                    buf = buf[i+1:]          # 假帧头，滑窗
                    continue
                a, b_, c, ts = struct.unpack("<fffI", body)
                kind = "ODOM" if cmd == 0x51 else "ATT"
                yield (kind, a, b_, c, ts)
                buf = buf[i+20:]

# ---- 使用示例 ----
link = BluePillLink("COM17")                      # 端口用 link_probe.py 探测（USB 主链 0483:5740 / BT04 备链）
print(link.cmd("PING", expect="PONG"))            # 判活
print(link.cmd("LINK ?"))                         # 查指挥权（回 OWNER:USB / OWNER:UART）
print(link.cmd("LINK USB"))                       # ⚠️ 取回指挥权：非 owner 链路的命令会被 BUSY 拒绝
print(link.cmd("WD 500"))                         # 开看门狗（owner 链路断链自动急停）
print(link.motor_rpm(0, 60))                      # 必须读到 'M0:60RPM'
print(link.cmd("ODOM 1"))                         # 开位姿帧
threading.Thread(target=lambda: [link.cmd("PING", "PONG") for _ in iter(int, 1)],
                 daemon=True).start()             # WD 保活（<500ms 间隔）
for kind, a, b, c, ts in link.odom_frames():
    print(kind, round(a,2), round(b,2), round(c,2), ts)   # Ctrl-C 退出
```

## 10. FAQ

| 症状 | 原因 / 处置 |
|------|------------|
| open 卡 20s+ | 微软栈在建链，正常；超时给 ≥90s |
| COM 口找不到 | ① USB 链路的 COM 口：**烧录后需拔插一次 USB**；② BT04：SPP 实例随断链消失（小车复位后常见）→ 重连蓝牙后重跑 `link_probe.py` |
| **命令回 `BUSY:UART` / `BUSY:USB`** | **链路不是当前 owner** → `LINK ?` 查 owner，发 `LINK USB`（或 `LINK UART`）取回；`STOP`/`LINK ?` 不受门控 |
| 命令回 `LINK:OFF` | 目标链路被 `car_config.h` **编译期关闭**（`CAR_FEATURE_USB`/`CAR_FEATURE_UART`）=0，属配置而非故障 |
| 命令发了没应答 | ① 未读应答就发下一条（应答会混叠）② 固件 init 失败停机（复位后重试；仍无应答 = 死机，找下位机侧）③ USB 链路确认顶层链路 |
| 收到没发过命令的 `USB READY` / `USB LOST -> UART TAKEOVER` | 异步行（指挥权广播），不是错乱 → 按行前缀分类解析即可 |
| 遥测成块丢行 | BT04 打包节拍 + 带宽超限 → 降频或 `REC+DUMP`；或改走 USB 主链 |
| `L 1` 回 LINE:ON 但车不巡线 | 巡线已编译剔除（当前固件），属预期 |
| 浮点应答少一位精度 | 固件禁 `%f`，只有 0.1 精度；精确读数用二进制/REC+DUMP |
