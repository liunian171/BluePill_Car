## 1. 背景与目标

| 项 | 内容 |
|----|------|
| 决策 | **USB 与 BT04 串口双链路并存** + 指挥权仲裁（用户拍板 2026-09-19） |
| USB 链路 | CDC 虚拟串口（PA11/PA12，0483:5740 → COMx），ROS 上位机主链，带宽 100KB/s 级 |
| UART 链路 | USART2 + BT04（9600-8N1，COM 口随配对漂移），离场遥控备份链 |
| 协议 | **零修改**——README §3 文本命令 + 0xAA 帧体系 + ODOM/ATT 上行帧，纯字节流语义与物理载体无关 |
| 核心诉求 | USB 主导；USB 失联串口自动接管；串口可显式接管/让出；USB 可显式抢回 |

## 2. 指挥权状态机（link_arbiter 组件核心）

### 2.1 状态与转移

| 状态 | 含义 | 应答/遥测/ODOM 路由 |
|------|------|--------------------|
| OWNER_USB | USB 主导（默认） | USB 链路 |
| OWNER_UART | UART 接管 | UART 链路（BT04） |

| 转移 | 触发 | 类型 |
|------|------|------|
| USB → UART | owner 链路发 `LINK UART` | 显式接管 |
| UART → USB | owner 链路发 `LINK USB`（= 让出）或 USB 链路发 `LINK USB`（= 抢回） | 显式切换 |
| USB → UART | **自动 failover**：usb_alive 由真变假（§4 三判据任一） | 自动，广播 `USB LOST → UART TAKEOVER` |
| UART → USB | ~~自动~~ **无**——USB 恢复仅广播 `USB READY`，不自动抢回（决议见 §4.2） | 显式 LINK 命令 |

### 2.2 命令语义表（新增 LINK 命令，注册进 txt_cmd）

| 命令 | 来源链路 | 行为 | 应答 |
|------|---------|------|------|
| `LINK ?` | 任意 | 查询当前 owner | `OWNER:USB` / `OWNER:UART` |
| `LINK USB` | 任意 | 切到 OWNER_USB | `LINK:USB OK` |
| `LINK UART` | 任意 | 切到 OWNER_UART | `LINK:UART OK` |
| `STOP` | 任意 | 急停（**安全例外，永远生效**） | 现有 STOP 语义 |
| 其他全部命令 | 仅 owner | 执行 | 非 owner 回 `BUSY:<owner>` |

**安全铁律：STOP 权限高于仲裁**——刹车权不归指挥权管。任何链路、任何状态、任何会话期，STOP 直达急停。

### 2.3 会话锁（调参保护）

`STEP / TEL / REC / ODOM / ITEL` 任一激活期间，`LINK` 切换命令拒绝，回 `BUSY:SESSION`——防止遥测流被切走一半导致上位机解析断流。`STOP` 不受限（急停本来就关闭所有会话工具）。

## 3. 双 ringbuf 与消费契约（防阻塞设计）

### 3.1 拓扑

```
ISR 层:   USART2 RX 中断 → uart ringbuf（现状不动）
          USB LP 中断(CDC_Receive_FS) → usb ringbuf（新增，只写不解析——ISR 铁律不变）
主循环:   每轮轮询消费两个 ringbuf → 命令带"来源链路"上下文执行 → 应答按仲裁路由
```

**必须双 ringbuf**：现有 ringbuf 为单生产者设计，两个 ISR 抢写会竞态。各 256B（UART@9600 = 266ms 防线；USB 靠时间片兜底）。

### 3.2 消费三机制

| 机制 | 内容 | 解决的威胁 |
|------|------|-----------|
| ① 命令级交织 | 每轮主循环轮流扫两 buf，执行完一条命令再回来读下一条（非"清空所有再执行"） | 双链路互相饿死 |
| ② 每轮时间片封顶 | 每轮命令解析预算 2ms（或每链路 ≤3 条命令），超限停手进控制节拍，积压下轮续 | 上位机猛发数据饿死 50ms 控制环 |
| ③ 发送按链路分治 | USB CDC 发送非阻塞 µs 级；UART 阻塞发送仅存在于 owner=UART 场景（低频遥控工况，够用） | 应答/遥测阻塞主循环 |

### 3.3 延迟上界与丢字节策略

- **STOP 最坏响应延迟 = 时间片 2ms + 一条命令执行时间**——毫秒级硬上界，与对端行为无关，无需特殊通道。
- 溢出丢新字节（现有行为）+ **新增溢出计数器**（OLED 诊断页/命令可查）——丢过数据必须可见。
- 丢字节后果与恢复：文本行损坏 → 解析失败回 `?`；二进制帧缺尾 → 既有 100ms 超时重同步。
- **已知限制（既有，不在本期解决）**：单条命令内部阻塞（如 DUMP ~1.3s）时间片管不了；DUMP 属调参会话锁定期，此时另一链路无人发命令，可接受。

## 4. USB 判活与恢复感知

### 4.1 判活信号（相与）

| 信号 | 采集点 | 含义 |
|------|--------|------|
| `dev_state == USBD_STATE_CONFIGURED` | 主循环每轮查 `hUsbDeviceFS.dev_state`（µs 级） | 枚举完成（插线/PC 重新启用/驱动重绑定均触发） |
| `DTR == 1` | `CDC_Control_FS` 的 `SET_CONTROL_LINE_STATE` 捕获存静态变量 | 上位机真正打开串口 |

`usb_alive = 枚举完成 && DTR`。failover 边沿：真→假即切 UART；假→真即广播一次 `USB READY`（不抢回）。

### 4.2 设计决议（用户确认 2026-09-19）

1. **USB 恢复不自动抢回**：任何串口工具打开 COM 口都会拉 DTR，自动抢回会造成运行中指挥权跳变。恢复后仅在 owner 链路提示 `USB READY`，需 USB 侧显式 `LINK USB`。
2. **调参会话期锁仲裁**：见 §2.3。

### 4.3 供电与噪声备忘

- USB 调试会话**只让 USB 供电**，ST-LINK 保持三线（SWDIO/SWCLK/GND）。
- 接电机主电源后若 USB 间歇掉线：先查共地与走线（地弹/EMI 耦合 D+/D-），必要时磁环。观察项，登记于调试总结。
- F103 烧录软复位后 USB 不重枚举（设备描述符请求失败/问题码 43），**拔插一次 USB 即愈**——flash 流程固化步骤：烧录 → 拔插 USB → 验证枚举。

## 5. car_config.h 开关设计

| 宏 | 默认 | =0 语义（空壳替换模式） |
|----|------|------------------------|
| `CAR_FEATURE_USB` | 1 | usb ringbuf 不消费 / `usb_alive` 恒假 / 仲裁固定走 UART——**USB 中间件代码仍在**（CubeMX 生成，12KB Flash 成本已付，编译剔除需动生成代码，不值） |
| `CAR_FEATURE_UART` | 1 | 不 init UART 接收 / UART 发送 no-op（stub 化 uart_platform_ops）/ 仲裁固定走 USB |

开关只作用于**组装层接线 + CMake 源取舍**（组件层零 include，遵守 car_config.h 铁律）；两链路宏双 0 无意义（车失联），CMake 期报错拒绝。

## 6. 看门狗语义升级

现有 WD（`WD <ms>`）改为**只盯 owner 链路输入**：owner 切换时喂狗基准重置；非 owner 链路的字节不喂狗。failover 本身即最快的断链响应，WD 作为 owner 断链的第二道兜底不变。

## 9. 附带收益与关联待办

- **提速待办（开发跟踪 ②）改道**：ODOM 50Hz（20ms 周期）不再依赖 USART2 提速——USB 主导时直接满足，提速决策可关闭或转"仅蓝牙场景"。
- 阻塞发送类已知限制（README §3.11）在 USB owner 下自然消失；UART owner 时沿用分频应对。
