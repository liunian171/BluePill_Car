## 1. 分层模型与各层性质

> 🔶 层命名 2026-09-11 修订（双栈模型）：旧命名来自单链视角，按数据角色重命名。**代码目录尚未迁移**，本节为概念层定义，文件迁移随实施期进行；旧名对照见 1.3。

### 1.1 双栈总览：全库共 5 类数据链

业务层只做"物理量 → 运动意图"的纯软件决策；其下方两条镜像链——感知栈（裸数→物理量，上行）与执行栈（意图→寄存器，下行）。加上正交的输入/输出服务，全库数据链清单：

| 链类别 | 方向 | 具体链 | 现状 |
|--------|------|--------|------|
| 命令链（输入服务） | 外→内 | BT04 → ringbuf → txt_cmd/帧解析 → 分发 → 应答 | ✅（分发待收编，评审 C1） |
| 感知链 ×3（上行） | 裸数→物理量 | IMU→姿态；灰度→线位置；编码器→里程/转速 | ⚠️ 姿态混在 imu_bridge、线位置混在 line_follower、里程半成（enc 已参数注入） |
| 决策（中枢） | 物理量→意图 | line_follower 状态机 | ✅（剥离感知部分后即达标） |
| 执行链 ×2（下行） | 意图→寄存器 | 速度环→电机；转向→舵机 | ⚠️ 混在 main.c（评审 C3） |
| 显示链（输出服务） | 内→外 | main 100ms → OLED 8 页组版 | ✅ |

### 1.2 各层定义

| 层（新名） | 核心职责（一句话） | 包含对象（现状） | 参与的链 | 禁止依赖 | 层归属判据 |
|-----------|-------------------|-----------------|---------|---------|-----------|
| **组装层**（旧: 应用层） | 创建全部实例 + 按节拍接线 + 接管权仲裁 + 显示组版 | main.c 用户区 | 所有链的汇聚点 | —（唯一允许直调 HAL 的高层） | 代码在 new/init 别的组件、决定"谁在什么时候跑" |
| **桥接层**（C 门面） | 语言边界：C 世界 ↔ C++ 对象，查 id → 转发 | motor/servo/imu/oled_bridge | 横切所有链 | — | extern "C" 函数 + 静态池，函数体只有寻址和转发 |
| **决策组件**（旧: 业务组件的一部分） | 消费物理量 → 产出运动意图（"车知识"：巡线策略、直角弯状态机） | line_follower.c | 决策（中枢） | HAL、任何硬件类型名 | 输入输出全是物理量/枚举，内部只有算法与状态机 |
| **感知组件**（新, 待建） | 裸数 → 可信物理量（"传感器知识"：校准、解算、补偿） | 姿态（待从 imu_bridge 拆出）、巡线感知（待从 line_follower 拆出）、里程计（半成） | 感知链 ×3 | HAL 直调（必须注入器件接口）、HAL_GetTick | 持有通道实例结构体，输入原始数据、输出单一物理量 |
| **执行组件**（新, 待建） | 运动意图 → 器件级目标（闭环控制：PID 速度环、转向模型） | 速度环（待从 main 拆出）、转向组件（待建，T1） | 执行链 ×2 | HAL 直调、HAL_GetTick | 输入意图与反馈物理量，输出器件级目标（RPM/脉宽） |
| **执行对象层**（旧: 功能对象层） | 器件级目标 → 器件语言（语义翻译：钳位/死区/RPM→千分比/角度→脉宽） | Motor、Servo（motor.cpp/servo.cpp） | 执行链 | HAL、具体协议类 | 持有器件接口引用（构造注入），只做换算与钳位 |
| **器件层**（补名, 无旧名） | 器件语言 ↔ 寄存器读写（真值表/脉宽/寄存器映射） | TB6612MotorProtocol、PWMServoProtocol、MPU6050（IIMU 接口+实现） | 感知链 + 执行链的底端 | 组合逻辑（公式归上层） | 一个器件一个类，翻译规则只属于这一个器件 |
| **驱动策略层** | 组合 ops 原语 + 纯计算（读→算→写） | pwm.c、encoder.c、uart.c、usergpio.c | 所有链的底端通道 | **HAL/CubeMX 头**（含间接 include） | 跨平台通用，void* 句柄 + ops 表 |
| **驱动平台层** | 唯一碰 HAL/寄存器的地方，原子操作 | *_platform_ops.c、i2c_hardware_ops.c | 同上 | 组合逻辑（公式归策略层） | 每芯片一套，接口签名不变 |
| **通用算法层**（common） | 零业务零硬件的纯数学/数据结构 | pid、imu_filter、ringbuf、tool | 被所有链调用 | HAL、业务头 | 换整车项目也能原样带走 |

> 协议接口（IMotorProtocol/IServoProtocol/IIMU 等 C++ 抽象类）不单独立层——它们是**器件层对上暴露的接缝**，定义"翻译意图"，随器件层走。

**决策组件接口面板（交界不拥有）** 🔶：决策组件与外界的全部接触面只有 4 个——① 感知接口（入：物理量，来自感知链顶层）② 意图接口（出：运动意图，交给执行链顶层）③ 时间基准（入：now_ms，来自组装层）④ 使能开关（入：enable/接管权，来自组装层）。它与两栈顶层只**交界数据，不持有实例、不调用实现**。检验标准：删掉全部 .c 只留接口头文件，决策组件代码应一行不改。

### 1.3 旧结构与命名的问题（修订原因）

| # | 问题 | 后果 |
|:---:|------|------|
| 1 | **单链视角**：旧模型是一条竖线（应用→桥→功能→协议→驱动），感知与执行塞进同一条链 | 姿态（感知）在链上没有位置 → 被塞进桥（胖桥 imu_bridge）；灰度读取混进决策（line_follower 直调 HAL，C2） |
| 2 | **命名按技术性质、不按数据角色**："业务组件"既装决策又装感知；"功能对象"不表意；AGENTS.md 4.1 的"业务对象"一词与指南漂移 | 新成员对号入座困难，组件边界模糊导致逻辑长错地方 |
| 3 | **组装层无名化**：main 被叫"应用层"，但它的真实职责（实例创建/接线/仲裁）没有名字 | 职责边界失守，业务持续涌入 main（上帝模块，评审 C3）的温床 |
| 4 | **器件层缺位**：TB6612Protocol/MPU6050 这类"器件翻译"长期无层名 | 归属随意：MPU6050 被堆 new 进桥、舵机命令域被放进 main |
| 5 | **两栈深度不对称未被表达**：感知栈 3 级、执行栈 4 级（执行侧多一层执行组件做闭环） | 看不出 imu_bridge 的校准管线"应该去哪"，也看不出速度环"应该在哪" |

**性质要点**：

- **跨平台承诺**：决策/感知/执行组件 + 执行对象 + 器件层 + 驱动策略层，换芯片或换整车时零修改。为兑现，头文件也不得 include CubeMX 头（pwm.h 现状 include tim.h 为 ⚠️ 反例，评审 C6）。
- **多态选择规则** 🔶：**平台多态**（换 MCU 芯片）用 C ops 函数指针表；**协议多态**（换驱动器件/传感器件）用 C++ 抽象接口注入。禁止在平台层用虚函数（C 世界进不来）、在器件层用 ops 表（丧失构造注入与类型安全）。
- **同构资源数组化** 🔶：N 个同类硬件一律"数组 + id"访问（pid_spd[2]、spd_target[2] 为范本），禁止分立变量 + 三元选择散落调用点（main.c 的 henc1/henc2 写法为 ⚠️ 反例，评审 S1）。

| 宏/常量 | 全大写下划线 | MAX_MOTORS、SERVO_LIM_L | — |

### 2.2 注释模板

| 位置 | 必须写什么 | 范本 |
|------|-----------|------|
| 文件头 | 分层架构图（ASCII）+ 本文件在哪一层 + "换平台/换器件时动不动这个文件" | pwm.h、uart.h、motor.h |
| ops 每个函数指针 | **三要素：是否阻塞 / 超时上限 / ISR 安全性** 🔶 | uart.h（"阻塞发送，返回 0/-1"为达标范本；pwm.h 一句话注释为待补齐范本） |

## 3. 关键机制使用规则

### 3.1 ops 函数指针表（平台多态）

- **规则**：进 ops 的必须是"原子操作"（start/stop/读寄存器/写寄存器）；含公式计算的组合逻辑一律放策略层——否则每个平台都要重复实现一遍公式（pwm.h 头注释已固化此分界线）。
- **句柄纪律**：平台句柄在结构体里必须是 `void *`，由平台层自行强转；HAL 句柄不得裸露在跨平台头文件中（`&hi2c2` 被当句柄解引用 → 硬错误，见调试总结 §1）。

### 3.2 C++ 接口注入（协议多态）

- **规则**：功能对象持有抽象接口**引用**（`IMotorProtocol &protocol`，motor.h），构造时注入；对象生命周期内引用不可空。
- **接口先于使用者**：C++ 前向引用规则——抽象类必须定义在使用它的类之前（motor.h 头注释第 1 条）。

### 3.3 静态池 + placement new（内存模式）

- **规则**：一切 C++ 对象用 `static uint8_t pool[N][sizeof(T)]` + placement new 构造（motor_bridge.cpp 为范本）；**禁堆 new/malloc**——heap 仅 512B，分配失败静默返回 NULL → 解引用即硬错误（调试总结 §5）。
- **伴生义务**：每个静态池必须配 id 越界检查（见 §4 义务 6）。

### 3.4 事件回调（诊断外泄）

- **规则**：业务组件不直接发串口，通过注册回调外泄事件（`line_follower_set_event_cb`，line_follower.h）；高频诊断事件与命令应答分走两条通道（tx_raw 不占应答页，main.c 注释）。

### 3.5 时间基准外部化

- **规则**：逻辑层/组件层禁止硬调 `HAL_GetTick()`，tick 一律由调用方作参数传入（`line_follower_update(now_ms, ...)` 为范本）；HAL_GetTick 只允许出现在 main.c 应用层与 ISR。
- **超时/周期值**：一律宏定义具名，禁止裸数字（§5.3 铁律 4）。

## 4. 模块衔接契约（新增部分必须满足的义务）

### 4.1 全局数据流四链

任何新模块先在这张图上找到自己的位置，再定义接口：

| 链 | 路径 | 节拍 |
|----|------|------|
| 命令链 | BT04 → USART2 ISR → ringbuf → main 主循环 while 清空 → 解析（txt_cmd / 内联帧）→ 执行 → 应答 | 事件驱动 |
| 控制链 | line_follower_update → spd_target/spd_dir → PID 速度环 → motor_bridge_set_speed_rpm | 50ms |
| 状态链 | 编码器 → PID 反馈；IMU 校准进度 → line_follower_try_auto_start | 随控制/显示 |
| 显示链 | 100ms 节拍读 IMU/编码器 → OLED 页 0-7 组版；ack → 页4；cmd_note → 页6 | 100ms |

### 4.2 衔接义务清单（8 项，逐项含后果）

| # | 义务 | 要求 | 违反后果 | 依据 |
|:---:|------|------|---------|------|
| 1 | **接管权声明** | 任何手动控制指令执行前必须退出巡线（现状 `line_follower_enable(0)`，未来为集中仲裁） | 50ms 后 spd_target 被状态机覆盖，急停后车"复活" | 调试总结 §12（实车事故） |
| 2 | **0 速必停语义** | 速度目标 < 1 RPM 时必须 pid_reset + 物理刹车，不得保留旧 PWM | "M0 0" 不停车 | 开发跟踪 W0-3 |
| 3 | **应答回执** | 命令类模块必须回 ack()（手机可见）+ cmd_note()（OLED 页6）；高频诊断走 tx_raw 独立通道 | 无线调试时"收到了但不知道执行没执行" | 开发跟踪 RSP 页决策记录 |
| 4 | **OLED 页申请** | 页 0-7 已全部分配（IMU/转速/编码器/灰度/应答/PID/命令/状态），新信息需申请复用或合并，禁止抢占 | 显示互相覆盖 | 工程文档显示定义 |
| 5 | **时间基准传入** | 组件 tick/周期判断用调用方传入的 now，超时值用具名宏 | 逻辑层锁死 HAL，PC 桩不可行 | §5.3 铁律 4 |
| 6 | **id 越界检查 + 静默失败禁令** 🔶 | bridge/组件 init 与运行时接口必须查 id/参数合法性；非法输入**不允许无声 return**——至少走一次错误通道（现状：串口错误输出或返回码，二选一，模块内保持一致） | 未初始化/越界调用被吞掉，表现为"指令无响应"类玄学问题，排查成本远高于一行检查（servo_bridge 有检查、motor_bridge init 没有的不一致为现存 ⚠️） | 静默失败与调试总结 §5 堆分配惨案同族 |
| 7 | **PC 桩先行** 🔶 | 新业务/算法组件必须可在 PC gcc 编译（零 HAL、时间外部化），配套 test/host_xxx_test.c 用例 + 测试点清单（测试项/输入/预期日志/是否需仪器） | 业务逻辑只能上实车调试，迭代成本 ×10 | §5.3 铁律 2/5；txt_cmd 41 用例为范本 |
| 8 | **单位与坐标域声明** | 跨模块接口的参数必须在头文件声明单位（RPM/0E3/µs/°）与坐标域（如舵机命令 = 输出域绝对角，直行 = -90） | 单位/域混淆 → 满舵、越限类事故（SV -90 曾被双算成 -180） | 舵机设计文档 §3 修订原因 |

### 4.3 main.c 五个动刀位置

新模块集成时只允许动这五处（均在 USER CODE 区内）：

| 位置 | 内容 | 纪律 |
|------|------|------|
| ① PV 区 | 句柄定义、静态池、模块状态变量 | g_ 前缀；标定值入 car_config 或具名宏 |
| ② USER CODE 2 初始化区 | 按依赖序 init | **安全铁律**：舵机回中位先于巡线初始化；init 失败走 Error_Handler |
| ③ 命令分发区 | TXTCMD case / 二进制 cmd 分支 | 每分支履行义务 1/2/3；解析归 txt_cmd，main 只做执行 |
| ④ 50ms 控制区 | 组件 update 调用 | 时间基准传入 now |
| ⑤ 100ms 显示区 | OLED 组版 | 定宽整行写，禁止裸清屏 |

### 4.4 时序约束表（硬边界）

| 约束 | 值 | 原因 |
|------|-----|------|
| ringbuf 消费 | 主循环 while 一次清空 | 逐字节消费丢帧（调试总结 §9） |
| 控制周期 | 50ms | 巡线采样 + PID 节拍 |
| 显示周期 | 100ms，与命令解析分离 | I2C 阻塞不得拖累命令响应 |
| I2C 超时 | 10ms | 100ms 曾造成命令延迟 5s（调试总结 §9） |
| 二进制帧超时 | 100ms 丢弃重同步 | 无线吞帧尾防卡死（main.c） |
| UART 发送 | 阻塞式，9600 波特率下注意字节数 × 1.04ms/字节 | 高频大帧会吃掉主循环预算 |
| Flash 占用 | 每次改动看链接输出，> 90% 预警 | 64KB 紧约束（§5.2 铁律 5） |
