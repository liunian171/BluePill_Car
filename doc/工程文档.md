## BT04 蓝牙串口模块（2026-09-09 实测建档）

### 已确认属性（PC/真机实测）

| 属性 | 值 | 证据 |
|------|-----|------|
| 蓝牙名称 | `BT04-A` | 手机 APP / Windows 配对列表 |
| MAC 地址 | `98:DA:20:04:5F:4F` | PnP 设备树 |
| 协议 | **双模**：经典蓝牙 SPP（服务 UUID 00001101）+ BLE GATT（服务 FFE0） | Windows 设备管理器 PnP 枚举 |
| 透传波特率 | 9600-8N1（与 main.c 固件配置一致） | PING→PONG 实测 |
| PC 出口串口 | **COM14**（"蓝牙链接上的标准串行"，配对后自动生成） | `Win32_PnPEntity` 按 MAC 过滤 |
| 连接模式 | 单连接：手机 APP 内主动连 / PC 打开 COM14 即发起连接 | 实测 |
| 固件接法 | BT04 TX→PA3(RX)，RX→PA2(TX)，透传，无流控 | 接线 + 通信实测 |
| 无线命令时延 | 文本命令 30~63ms，二进制帧 31~94ms，**无丢包**（13+6 用例） | `tools/bt_cmd_test.py` 实测 |
| 配对 PIN | `1234`（出厂默认，配对弹窗时输入） | 2026-09-15 实测 |

### 使用要点

- **单连接互斥**：手机连上后 PC 打不开 COM14，反之亦然——测试前先断另一端
- PC 端测试：`python tools/bt_cmd_test.py COM14 --ping / --auto / --bin`（需 pyserial）
- 找不到 COM 口时按 MAC 过滤：`Get-CimInstance Win32_PnPEntity | ? { $_.PNPDeviceID -match '98DA20045F4F' }`
- **SPP 连接三态**（2026-09-15 沉淀，详调试总结 §19）：open 立即拒绝 = 口被占（查僵尸进程）；open 阻塞 20s+ = 栈在建链（正常）；写超时 = 设备不可达

### 待确认 ⚠️（未实测，勿臆测）

- AT 指令集与配置方式（改名称/波特率/配对码）：需 USB-TTL 直连模块 UART、按模块手册进 AT 模式试探——改透传波特率前**必须同步改 main.c**（当前 9600 硬编码于 USER CODE 段）

## USB CDC 虚拟串口（2026-09-19 上线，上位机主链）

| 项 | 值 |
|----|-----|
| 硬件 | PA11(D−) / PA12(D+)，DP 侧 1.5k 上拉 = R10（**外部固定**，固件无法主动断开总线） |
| 枚举 | `VID:PID = 0483:5740`，Windows 显示"USB 串行设备 (COMx)" |
| 传输 | USB FS bulk，波特率配置不适用；实测单命令往返 0.2ms、突发 40 条零丢（容量 239B 内） |
| 判活 | 枚举完成(`dev_state==CONFIGURED` 且 `pClassData!=NULL`) + 终端应用拉 DTR（`g_usb_dtr`，usbd_cdc_if.c 捕获） |
| ⚠️ 烧录后 | F103 软复位**不重枚举**（打开端口报错 31/43）→ 必须拔插一次 USB；用 `tools/flash_flow.py` 自动等待+验证 |
| 初始化 | CubeMX 生成：`MX_USB_DEVICE_Init()`（main.c）→ 中间件在 `USB_DEVICE/`（`usbd_cdc_if.c` 收包写 `g_ringbuf_usb`，ISR 只写不解析） |
| 分层归属 | **未单独立层**（指南 §1.2 缺口，见架构审计 P1-8）：`USB_DEVICE/` 属 CubeMX 生成中间件；收包路径直接写组装层 ringbuf，注入式改造已登记待办 |

> 双链路指挥权/门控/failover 语义权威 = `doc/双链路仲裁设计文档.md`；协议权威 = `README.md` §3。

## 软件架构（分层 ops 抽象模式，详 AGENTS §4.1 与 代码风格指南 §1）

```
Core/
├── Src/main.c                     ← 组装层：init 链 + 节拍接线 + 接管权仲裁 + 遥测/显示
├── Src/common/                    ← 通用算法层（零 HAL）
│   ├── ringbuf.c                  │  环形缓冲区（串口中断收字节）
│   ├── imu_filter.c/h             │  Mahony 四元数滤波 + 零偏校准（纯 C 化 2026-09-15）
│   ├── pid.c/h                    │  增量式 PID（含抗饱和）
│   └── tool.c/h                   │  工具函数
├── Src/driver/                    ← 各层（自顶向下）
│   ├── txt_cmd.c/h                │  文本命令解析（纯逻辑, PC 桩可编译）
│   ├── steering.c/h               │  执行组件: 转向（限位/域换算/状态保持）
│   ├── speed_loop.c/h             │  执行组件: 速度环（测速/PID+前馈/停车语义）
│   ├── odom.c/h                   │  感知组件: 里程计（增量位姿 ΔX/ΔY/Δθ）

│   ├── line_follower.c/h          │  决策组件: 巡线四状态机（直调 HAL 待治理）
│   ├── motor_bridge / servo_bridge / oled_bridge / imu_bridge  ← 桥接层 (C 门面, init(cfg)→返回码)
│   ├── motor.cpp + motor_protocol │  执行对象层 Motor + 器件层 TB6612MotorProtocol
│   ├── servo.cpp + servo_protocol │  执行对象层 Servo + 器件层 PWMServoProtocol
│   ├── mpu6050.cpp + imu_base     │  器件层 MPU6050 + IIMU 接口

│   ├── uart.c/h + uart_platform_ops.c                │  UART 策略/平台

│   ├── oled_bridge.cpp/h          │  OLED C 桥接层
│   └── oled_font.h / oled_font_data.c                │  字库
```

> **组装层定位（脑干模型，2026-09-19）**：大脑=上位机（任务规划/SLAM/定位）· 小脑=决策组件（行为反射）· 脊髓/前庭=执行/感知组件 · **脑干=组装层**（节拍/接管权仲裁/STOP·WD 安全/OLED 与上行组帧——只裁决不思考）。新自主能力 = 新决策组件，永不往 main.c 加"脑力"。权威声明见 `doc/代码风格与模块衔接指南.md` §1.2。

## OLED 显示布局（8 页轮转：每 100ms 刷 1 页，8 页 800ms 一轮）

```
页0  R:x.x P:x.x Y:x.x     ← IMU 欧拉角
页1  M0:实->目  M1:实->目   ← 速度环 实际->目标 (带符号)
页2  ENC0:x  ENC1:x        ← 编码器计数
页3  G:10101  CAL/OK       ← 灰度 + IMU 校准状态
页4  RSP:...               ← 最近应答 (无线调试确认)
页5  P:x,x I:x,x D:x,x     ← PID 增益 (×100, 真值从组件读)
页6  CMD:...               ← 最近执行的命令
页7  L:<owner> USB:ON/OFF U:<秒>  ← 链路状态+健康计数（2026-09-19 起替换原巡线状态页）
     异常态挤占 USB 字段: E<n>=OLED写失败累计 O<n>=ringbuf溢出累计 FZ=OLED熔断停刷
```

## 串口协议

> **上位机对接的完整权威 = [`README.md`](../README.md) §3**（上行四类/下行两类/帧格式/时序带宽/示例代码），本节仅作索引速查。

### 命令帧（PC → STM32，二进制）

```
0xAA | cmd | [参数...] | 0xFF | 0xFF     浮点 = IEEE-754 小端
```

| CMD | 参数 | 说明 |
|------|------|------|
| 0x01 | id + float(rpm) | 电机目标转速（带符号） |
| 0x02 | id + float(m/s) | 电机线速度 |
| 0x03 | id | 刹车 |
| 0x10 | 0x00 + float(°) | 舵机角（输出域，直行 -90） |
| 0x20 | id + float(%) | 开环占空比 −100~100（2026-09-14 实现） |
| 0xE0 | id + float×3 | PID 增益 |
| 0xF0 | 无 | 心跳 → 应答 PONG |
| 其它 | — | 应答 `?` |

> 旧设计的 0x04/0x11/0x12/0x30/0x31/0xF1 及 0xA0 状态码响应帧属 uart_cmd_parser 时代稿，**从未实现**，该文件已于 2026-09-13 删除。

### 上行（STM32 → PC）

| 类别 | 触发 | 内容 |
|------|------|------|
| 开机横幅 | 复位一次 | `UART2 Ready`（init 判据用 PING→PONG 更可靠） |
| 命令应答 | 每命令 | `M0:60RPM` / `SV:-90.0` / `STOP OK LINE OFF` 等文本 |
| 遥测（按需） | `TEL/STEP/DUMP` | CSV 文本（闭环 10Hz / 阶跃 20Hz / 机内记录重放） |
| 位姿帧（按需） | `ODOM 1` | **ODOM 0x51 @20Hz**（ΔX/ΔY/Δθ f32 + ts u32）+ **ATT 0x52 @10Hz**（roll/pitch/yaw） |
| 看门狗 | `WD <ms>` 使能 | 超时无下行字节 → 急停 + `WD TIMEOUT STOP` |
| 巡线事件 | `L 1` | 状态机跳转诊断文本 |

### 文本命令速查

`PING` `STOP` `M0/M1/MS <rpm>` `B0/B1` `P<id> kp ki kd` `S` `L/LA 0/1` `GK/GD/GS` `GI` `GC/GT` `E<id> <ppr>` `SV/SV±/SL/SR/SC` `STEP` `TEL` `FF` `REC` `DUMP` `ODOM 0/1` `WD <ms>` `ITEL/IGAIN/IDRIFT/IRATE/ICAL`（IMU 工具链五条，2026-09-15）— 完整语义见 README §3.7。

## 初始化流程

```
HAL_Init()
  └→ SystemClock_Config (HSE+PLL=72MHz)
    └→ MX_GPIO/TIM1/TIM2/TIM3/USART2/TIM4/I2C2_Init()

User Code（任何 init 失败 → Error_Handler() 停机）:
  ├── UART: 覆盖波特率 9600 → ringbuf_init → HAL_UART_Receive_IT(1字节)
  ├── 编码器: henc1/henc2 (TIM2/TIM3, PPR=1466 实测) → encoder_start
  ├── PWM: TIM1 CH1/CH2 20kHz 归零启动
  ├── 电机桥: motor_bridge_init(0/1, &g_motor_cfg)  ← 配置注入, drive_sign={1,-1}
  ├── 速度环: speed_loop_init(&g_spd_cfg, &g_spd_io)  ← SIMC 参数 87/40/0, ff=1.0
  ├── 舵机桥+转向: servo_bridge_init → steering_init(输出域 [-115,-65], 直行 -90) → steering_center
  ├── OLED: oled_bridge_init(&g_oled_cfg)  ← 写事务注入
  ├── 巡线: line_follower_init(30,10) + 事件回调
  ├── IMU: imu_bridge_init(0, &g_imu_cfg)  ← 静态池, tick 注入
  └── 里程计: odom_init(&g_odom_cfg, &g_odom_io)  ← yaw_sign=-1 (安装适配)
```

## 主循环

```
while(1):
  ① ringbuf 清空 → 文本命令(txt_cmd) / 二进制帧分发（0xAA 头, 100ms 超时重同步）
  每 50ms:  看门狗判定(WD 使能时) → line_follower_update → speed_loop_update
            → odom_update（ODOM 1 时发 ODOM 0x51 @20Hz + ATT 0x52 @10Hz）
  每 100ms: 读编码器 + OLED 单页轮转
            （IMU 滤波为独立节拍 ③b: 周期 g_imu_period_ms 由 IRATE 可调 20~1000ms 默认 100ms，
             并按 ITEL 模式携带 IMU 遥测；2026-09-15 起不再与显示块绑定）
```

## IMU 滤波算法（common/imu_filter.c，2026-09-15 纯 C 化）

- **Mahony 四元数**（Kp=0.5, Ki=0）+ 启动零偏校准 + 静止漂移补偿
- 加速度异常分级降权（远离 1g 时降权/清零修正）
- `halfez = 0`：IMU-only 无航向观测，accel 不修正 yaw（2026-09-14 修正入库）
- ~~yaw 跟踪失真专案~~ ✅ **已关闭**（2026-09-15：根因=漂移补偿误吸收旋转，加陀螺模值门限修复，三级闭环见调试总结 §20；算法现居 attitude.c 漂移跟踪段，默认门限 1.5°/s）
