# R3 发送路径专项设计（3a + 3b）

> 配套: AGENTS.md §5.1「改协议/架构先更新 doc」；README.md §3.11「已知限制」。
> 状态: 设计定案（2026-09-21）。代码落地后回写 README §3.11 与 §3.5(c)/§3.9。

## 一、问题现状（改造对象 app_tx）

`app_tx.c` 是两个原始发送出口（组装层 HAL 直调唯一收口）：

| 出口 | 现实现 | 问题（3a/3b 对症点） |
|------|--------|----------------------|
| `tx_usb` | `CDC_Transmit_FS` 忙轮询 ≤10ms 后**静默弃** | 静默失败不可见（3a）；忙轮询阻塞主循环（3b） |
| `tx_uart` | `HAL_UART_Transmit` **阻塞** ≤100ms | 每帧 9600 下 ~21ms 阻塞控制节拍（3b）；PA3 悬空 ORE 错误静默停摆，无 `HAL_UART_ErrorCallback` 重挂（3a） |
| 应答/遥测/broadcast | `app_tx_send_by_link`/`send_to_owner` 返回 `void` | 无统一失败语义、无计数（3a）；`DUMP` 逐行 `delay_ms(20)` 阻塞主循环 ~1.3s（3b） |

项目铁律（外设故障系统级设计决议）：**① 失败代价按控制节拍预算 ≤20ms；② 沉默失败必须计数可见；③ 辅助通道带熔断或移出控制节拍**。

## 二、设计方案（统一对称 `tx_stream` 核心）

新增**纯逻辑、零 HAL** 的 `common/tx_stream(.h/.c)` —— UART 与 USB 共用同一发送核心，
对齐 `cmd_exec`/`txt_cmd` 模式（全函数指针注入 + PC 桩可测）。

### 2.1 核心模型

```
 任务（生产者）            tx_stream（本模块）                 平台（app_tx，HAL 直调）
┌────────────┐   send()  ┌──────────────────────────┐   start()  ┌────────────┐
│ app_*      │ ────────▶ │  RingBuffer 字节队        │ ──seg──▶  │ HAL_UART_  │
│ send_by_link│            │  + seg[TX_SEG_MAX] scratch│   free()  │ Transmit_IT│
│ 等          │ ◀──────── │  分段发送状态机           │ ◀──────── │ CDC_Trans- │
└────────────┘            └──────────────────────────┘           │ mit_FS     │
                                                           也由 app_tx_service 轮询
```

- **队**：复用现有 `common/ringbuf`（SPSC，任务产/本模块消），新增 `peek`+`commit` 两个原子助手。
- **分段发送**：`service()` 若 `free()`=可收新段 且 队非空 → 把 `≤TX_SEG_MAX` 字节 **peek** 进 `seg` scrub →
  调 `io->start(seg,len)` → 返回 `START_OK` 才 `commit`（弹出队列）；`RETRY/ERR` 则**不消费**（数据不丢，留待下次）。
- **注入面**（平台只实现两个原子原语）：
  - `int (*free)(ctx)`：链路是否可收新段。UART=`huart2.gState==READY`；USB=`已枚举 && CDC_IsTxFree()`。
  - `int (*start)(seg,len,ctx)`：发起一段异步发送，返回 `TX_START_OK/RETRY/ERR`。
- **推进链**：`send()` 先入队，再 kick 一次 `service()`；任务主循环周期调 `app_tx_service()`（两流 while-drain）。
  - UART：`HAL_Transmit_IT` 置 `gState=BUSY_TX` → 下次 `free()`=false 停一段 ~50ms（自限速），GState→READY 后断续推 → **非阻塞自节拍**。
  - USB：`CDC_Transmit_FS` 置 `TxState=1` → `free()`=false 停一段 → IN 完成 `TxState=0` 后续推 → **非阻塞不丢包流式**。
- **统计**：`dropped`（队满丢字节）、`txerr`（start 失败）、`sent`（累计字节）—— 全都饱和计数、外部可查。

### 2.2 与旧实现差异（3a/3b 逐条闭环）

| 条款 | 旧 | 新 |
|------|----|----|
| 3a 统一失败语义 | 返回 void，失败静默 | `send_by_link`/`send_to_owner` 返回 `bridge_ret_t`；失败/丢弃在 `dropped/txerr` 计数，OLED 页7 可见 |
| 3a UART ErrorCallback | 无（PA3 悬空静默停摆） | main.c 增 `HAL_UART_ErrorCallback`：计数 + 重挂 `receive_IT` |
| 3b UART IT | `HAL_UART_Transmit` 阻塞 | `HAL_UART_Transmit_IT` + 队 + `free()`=gState 判闲 |
| 3b USB 非阻断不丢 | 忙轮询 10ms 静默弃 | 入队 + `free()`=TxState 判闲，Busy 留队续发，**不落地丢弃**（仅队满才弃并计数） |
| 3b DUMP 不阻塞 | 逐行 `delay_ms(20)` | 改流式：按 `tx_stream_pending` 阈值门控，随 50ms 节拍逐行吐，去阻塞延时 |
