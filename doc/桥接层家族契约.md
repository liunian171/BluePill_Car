## 2. 契约正文

### 2.1 形状：门面只做三件事

`查 id → 校验参数 → 转发`。**桥内禁止**：业务逻辑（校准/滤波/映射）、I/O 输出（串口/OLED）、HAL 直调、标定值硬编码。

### 2.2 init 签名统一

```c
bridge_ret_t xxx_bridge_init(uint8_t id, const xxx_cfg_t *cfg);
```

- 参数**打包成配置结构**（`xxx_cfg_t`）而非长参数列表：motor 现有 7 个参数，且方向符号还要加；打包后**加参数不动调用点**。
- 返回 `bridge_ret_t`：init 是低频、可失败、调用方必须处理的接口（组装层失败 → `Error_Handler`）。
- 唯一豁免：`oled_bridge_init(const oled_cfg_t *cfg)` —— **单例，不带 id**（见 §2.7）。

### 2.3 错误通道形态：**返回码**

- 桥家族统一用 `bridge_ret_t`（**不做串口/OLED 输出**——桥保持零依赖，PC 桩才能编译；输出归组装层）。
- **动作类**（`init` / `set_xxx` / `start` / `stop` / `brake`）→ 返回 `bridge_ret_t`。
- **取值类**（`get_xxx` / `ready`）→ 保持值返回（不能塞返回码），越界/未初始化必须返回**头文件注明的安全默认值**（例：`imu_bridge_get_roll` 越界 → `0.0f` 且头文件写明"默认值不可当真实姿态用"）。
- **静默失败禁令的落点**：非法输入必须"有码可查"，不得 `return;` 了事。
- 热路径消费约定：50ms 控制链上的桥调用**显式写 `(void)`** 表示"有意忽略"，不靠"返回值没人接"表达。

### 2.4 内存：静态池 + placement new

- 每个桥一套 `static uint8_t xxx_pool[XXX_MAX][sizeof(ConcreteType)]` + `static Type *inst[XXX_MAX]`。
- 容量宏 `XXX_MAX` 定义在桥头文件；init 先查 `id >= XXX_MAX` 再落池。
- **禁堆 `new`**（heap 512B，分配失败即硬错误；调试总结 §5）。

### 2.5 校验：id 与 handle 都要查

- `init`：`id >= XXX_MAX` → `BAD_ARG`；`cfg == NULL` → `BAD_ARG`；`handle == NULL` → `BAD_ARG`；枚举/区间不成立 → `BAD_CFG`。
- 运行时：`id >= XXX_MAX` 或该 id 未初始化 → `ERR_NOT_INIT` / `BAD_ARG`。
- **未知协议/类型枚举不得静默 break**（现状 `servo_bridge` default 分支）→ `BAD_CFG`。

### 2.6 知识归属：方向/极性 → 配置注入

驱动侧方向符号进 `motor_bridge_cfg_t.drive_sign`（**删除 `if (id == 1)` 特例**）；反馈侧符号进速度环标定表 `fb_sign`。
两者**必须镜像**，故要求在组装层**相邻声明**（同一张配置区，一眼可查），并在两处注释互相指认。

> 判据：桥不知道"哪台车反向接线"，只知道"这个通道的方向符号是 +1/-1"。

### 2.7 单例豁免：仅 `oled_bridge`

- **事实**：单屏是硬件事实，双屏是投机需求（YAGNI）。
- **豁免范围**：运行时接口（`oled_bridge_show_*`）**不带 id**；`init` 仍用配置结构 + 返回码，形状与家族一致。
- **I2C 注入照做**：`oled_driver` 禁止硬编码 `&hi2c2`、禁止 include CubeMX 头；改为注入"写事务"函数（`oled_write_fn`），HAL 绑定落到平台侧文件 `oled_platform_ops.c`（与 `pwm_platform_ops.c` 同构）。
- **触发归一的条件**：出现第二块屏或第二路 I2C 时，把 `oled_cfg_t` 加 `id` 并给运行时接口补 id 参数——届时按本契约执行，不额外设计。
- **接口裁剪（2026-09-19 Flash 瘦身批次）**：运行时接口收敛为三条 —— `oled_bridge_show_string_small`(6×8 指定列) / `oled_bridge_show_line_small`(6×8 整行单事务) / `oled_bridge_tx_fail_count`+`oled_bridge_fused`(诊断)。
  原 `oled_bridge_show_string`(8×16) 与 `oled_bridge_show_chinese`(16×16 汉字) **已删除**：无调用者，且携带 8×16 字库 ≈1.6KB。需大字号/汉字时从 git 历史取回字库与接口，并重新 configure（判据见代码风格指南 §7）。

## 3. 家族边界（桥不做什么）

| 不做 | 归属 |
|------|------|
| 校准状态机 / 漂移补偿 / 滤波调度（imu 现 ~90 行） | 感知组件（C3） |
| 行程钳位 / 域换算 | 执行组件（已落地：`steering` / `speed_loop`） |
| 串口/OLED 错误输出 | 组装层 |
| 具体器件的寄存器时序 | 器件层（`TB6612Protocol` / `PWMServoProtocol` / `MPU6050` / `OledDriver`） |
