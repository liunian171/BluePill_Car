### 📐 设计决议：功能编译开关（car_config.h）与双模式定位（2026-09-19）

**背景口径**：当前小车主职 = **ROS 小车下位机**（接收上位机命令 + 上行感知帧）；无上位机时保留独立小车能力。巡线功能暂时用不到 → 期望"不编译进固件"。

**① 现状判定：功能开关组件不存在，需实现**
- 运行时开关已有但分散：`L`（line_follower_enable）/ `WD` / `ODOM` / `TEL`——只做到"不接管"，代码仍烧进 Flash（line_follower.c 463 行 + txt_cmd 分支 + main.c 约 15 处调用点）。
- 编译期开关**为零**：CMakeLists `file(GLOB)` 全量编 driver/*.c，`target_compile_definitions` 空，main.c 无任何功能门宏。
- 已登记的 `car_config.h` 集中（待办 3②）原口径仅"标定集中"→ **职责扩展为：标定参数 + 功能编译开关**，一个头文件两件事。

**② 组件位置分析：开关属组装层知识**
- "这台车启用哪些功能"与 PPR/轮距同类 = 车的知识 → 归**组装层**。载体：`Core/Inc/car_config.h`（纯宏头文件），消费者**仅限组装层 main.c + CMakeLists**。
- 铁律：**组件层/桥接层禁止 include car_config.h**——组件依赖白名单仅 `<stdint.h>`（义务 7），功能宏进组件即破坏 PC 桩可编译性。开关只允许作用于两处：CMake 源文件列表、组装层接线。这与接管权仲裁天然同源（组装层是唯一决定"谁接管运动意图"的地方）。

**③ 巡线编译期剔除的接缝盘点**
| 接缝 | 位置 | 内容 |
|------|------|------|
| 组装层 | main.c | include / line_diag 回调 / init / **约 12 处 `line_follower_enable(0)`（接管权安全语义）** / TXTCMD_LINE_* 六个 case / 50ms tick / OLED 页 4 / try_auto_start |

### 📐 设计决议：双链路仲裁 USB+UART（2026-09-19）

**背景**：上位机链路由 USART2+BT04(9600) 迁移 USB CDC——独立测试固件（USB_ECHO_TEST）真机验证 PASS（枚举 0483:5740→COM17、PING/PONG 10/10 @0.1ms、随机回显 20/20 零丢包），硬件含 R10 上拉全部正常。验证前实锤 F103 坑：**烧录软复位后 USB 不重枚举（设备描述符请求失败/问题码 43），拔插一次 USB 即愈**——flash 流程固化此步。

**决策（用户拍板）**：USB 与 BT04 **双链路并存** + 指挥权仲裁，不做完全替换。

**核心设计**（权威全文见 `doc/双链路仲裁设计文档.md`）：
- 状态机 OWNER_USB（默认）/ OWNER_UART；`LINK USB / LINK UART` 一条命令承载 接管/让出/抢回 三语义；`LINK ?` 查询。
- 自动 failover 判据：dev_state≠CONFIGURED / DTR 掉落 / USB WD 超时；**USB 恢复不自动抢回**（仅广播 USB READY，防任意串口工具拉 DTR 造成指挥权跳变——用户确认）。
- 安全例外：STOP + LINK ? 任意链路直通；非 owner 命令回 BUSY:<owner>；调参会话（STEP/TEL/REC/ODOM/ITEL）激活期 LINK 切换回 BUSY:SESSION（用户确认）。
- **双 ringbuf**（uart/usb 各 256B）：现 ringbuf 单生产者设计，双 ISR 共写会竞态；主循环"命令级交织 + 每轮 2ms 时间片封顶 + 发送按链路分治"消费契约，STOP 最坏延迟毫秒级硬上界。
- 组件落点：`link_arbiter.c`（组件层纯逻辑，PC 桩可测）；USB 中间件代码保留（成本已付），链路开关只作用组装层接线；car_config.h 增 `CAR_FEATURE_USB`/`CAR_FEATURE_UART`（空壳替换模式）。
- 分期：P1 链路并存+路由 → P2 仲裁 → P3 开关收口；提速待办 ②（ODOM 50Hz）由 USB 链路直接满足，改道关闭。

### 📐 设计共识：脑区模型与组装层定位（2026-09-19）

**背景**：用户提出"组装层对接决策组件并控制其功能 = 大脑"模型。讨论后修正定位并达成共识：

| 脑区 | 对应 | 职责 |
|------|------|------|
| **大脑** | 上位机（ROS/人） | 任务规划、SLAM 建图、全局定位——一切"想"的部分 |
| **小脑** | 决策组件（line_follower） | 行为反射：感知物理量 → PD/状态机 → 运动意图，使能即自治 |
| **脊髓/前庭** | 执行/感知组件 | 速度环闭环 / 姿态融合（组件层硬件盲，注入边界） |

### 📐 设计决议：外设故障不得拖垮系统节拍（系统级完善，2026-09-19 登记 → **后置解决**）

**来源事件**：OLED 写超时 100ms × 排线接触不良 → 显示块 100ms 且自锁 → 主循环 pass 锁死 100ms → 速度环减半（ODOM 20→10Hz）。详 `doc/节拍拉长与I2C总线专案.md`、`调试总结.md` §24。

**问题抽象（是一类，不是一个）**：与外设（I2C 器件/显示/传感器）共处**同一条主循环**的阻塞式访问，其"异常代价"完全没有按控制节拍约束：
1. 超时按"够用"取值（100ms）而非按控制周期预算（应 ≤20ms 量级）
2. 失败后**每轮重试** → 单次故障被放大成**持续**故障；叠加"节拍基准在块首赋值"形成自锁（显示块每轮都到期）
3. 失败**沉默**（返回 void / 忽略返回码）→ 无人察觉、无法熔断、无计数

**三条通用原则（候选，正式定案时确认）**：
- **① 失败代价按控制节拍预算**：单笔外设超时 ≤ 控制周期的一定比例；"每轮重试次数 × 单笔超时"必须有硬上界
- **② 沉默失败必须可见**：所有"尽力而为"的辅助通道（显示/日志/非关键传感器）失败一律**计数 + 可查**
- **③ 辅助通道不得进控制路径**：显示/调试刷新必须带熔断（或分频/后台化），禁止无界重试

**范围候选（后置时逐条定序，不做散修）**：OLED（✅ 已按 ①② 落地补丁）/ MPU6050 I2C 失败（全零回退，本次伴生现象）/ UART 收发（⬜ 无 `HAL_UART_ErrorCallback`，出错后停摆）/ `ack()`+`tx_raw` 阻塞发送（README §3.11 已知限制）/ `DUMP` 逐行 20ms 阻塞 ~1.3s / `usb_send_raw` 的 USBD_BUSY 静默丢弃

**用户口径（2026-09-19）**：**后置解决** —— 本轮只按 ①②③ 对 OLED 落地（已完成），其余随 P3（瘦身/重构）批次统一治理；避免"逐个外设打补丁"的分散修改。

| 改动 | 收益（实测） | 说明 |
|------|------------|------|
| 紧凑 `sinf/cosf`（新增 `common/math_fast.c`，PC 桩 7/7） | **−4424B** | 本车只用 ≤2π 域，却链入 newlib 全范围范围规约链（`__kernel_rem_pio2f`+`two_over_pi`+`__ieee754_rem_pio2f`+kernels）；自实现 = fdlibm 二段规约 + 四次多项式，调用域误差 **4.76e-07** |
| 删 I2C2 事件中断（`it.c` 去 `HAL_I2C_EV_IRQHandler` 调用 + `i2c.c` USER CODE 区关 NVIC） | **−2920B** | 本工程 I2C 全阻塞式，无中断使用者；hal_i2c 5313→2361B |
| 删 8×16 字库 + `show_string/show_chinese`（死代码） | **±0B** | 该段**早已被 `--gc-sections` 自动剔除** → 删除属代码卫生（把"靠 gc 兜底"变成"显式不存在"） |
| **Release 启用 LTO**（`-flto` 编译 + 链接） | −7496B，**但真机 HardFault → 已回退** | ⚠️ LTO 版启动后锁死（`HFSR FORCED`+`CFSR IACCVIOL`、`uwTick` 冻结、无有效栈帧），现象落在 USB 重枚举前后；回退后同代码启动正常。**暂不启用**，后续专项 bisect |

**结果**：**Flash 62440B(95.28%) → 55096B(84.07%)，净省 7344B（−11.2%）**（①+② 两项；LTO 回退）；RAM 11832B(57.77%)；零新增告警。
**验证**：PC 桩八组全绿（105/33/54/30/24/ALL/16/**7**）；真机：无 LTO 固件 SWD 判活通过（`uwTick` 递增、CFSR/HFSR 全 0）；✅ **USB 链路冒烟 + 电机/舵机受控验证全过（2026-09-19，`.workbuddy/usb_smoke_test.py`）**：ODOM 20Hz（162 帧/ts 全 50ms）、ITEL 全非零、突发 40 条零丢；**电机 `M0/M1 30`→24~28、`M0 -30`→−25~−22（反向正确）、`MS 30` 双轮 25~28 不发散、`B0/B1` 刹车、二进制 `0x01/0x03/0x10/0x20/0xF0` 全通、`STOP` 收尾**；舵机 `SV -90/-100/SV±` 逐度吻合 —— **USB 链路可完整控制电机与舵机**（详调试总结 §26）。
