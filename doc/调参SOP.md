# 调参 SOP — PID 速度环辨识与整定标准流程

> 版本: v1.0 (2026-09-13)。基于 M0 全流程实跑验证（辨识→A/B 对照→参数回写，上升 90% 150ms/零超调）。
> 定位: 本工程操作规范（A 层）+ 可移植方法论（B 层，移植指引见 §7）。理论依据见《闭环控制分析报告》与 tools/step_ident.py 头注。

---

## 1. 适用范围与前置条件

- 适用: 任何"PWM/千分比 → 转速"的直流有刷电机速度环（本工程 M0/M1）；方法论可推广至其他一阶类对象。
- 前置检查（缺一不可，否则数据不可信）:
  1. **带符号测速**已启用（反馈保留方向）——丢符号的反馈会掩盖模型极性；
  2. **增量式 PID 抗饱和**已修复（钳位回写 prev_output）——否则闭环数据被积分饱和污染；
  3. 标定常量已实测（PPR / max_rpm / 轮径）——K 的物理校验依赖它们；
  4. 轮子悬空、电机供电正常、蓝牙链路连通（tools/bt_connect.py 验证 PONG）。

## 2. 总流程（五步）

| 步骤 | 内容 | 工具 | 产出 |
|------|------|------|------|
| ① 连接 | 扫口+PONG 探测，端口存档 | bt_connect.py | tools/data/bt_port.txt |
| ② 采集 | 开环阶跃，多工作点 × 5s | step_capture.py | step_m*_*.csv |

| ⑤ 回写 | 最优组设为上电默认 + 文档记录 | 编辑 main.c + git commit | 参数资产化 |

## 3. 操作细则

### 3.1 采集（步骤②）

- 每电机至少 **2 个工作点**（低/中，如 300‰ 与 600‰），验证增益线性度——离散 >15% 说明死区/摩擦显著，需在报告标注；
- 时长 5s：确保进入稳态（辨识器自动剔除刹车滑行帧并判稳）；
- 遥测分频：COM14 这类弱链路用 div=2（10Hz）；好链路可用 1（20Hz）；
- 判据：稳态段量化噪声 ±0.8 RPM（0.82 RPM/count 分辨率）属正常。

### 3.2 辨识（步骤③）

- **K = 稳态转速 / 阶跃量**（基线为 0，注意不是首帧采样值——响应快于采样时首帧已是中段）；
- 物理校验：满占空外推 = K×1000，应 ≈ max_rpm（±10%），偏离大说明数据或标定有问题；
- τ < 2×采样周期(100ms) 时按上界处理（对象近似纯增益，PI 极好整），不必强求精确值；
- 多工作点 K 取均值，离散度写进报告。

### 3.3 域换算（易错点，工具已内置）

- 辨识在"千分比域"（u=‰，y=RPM）→ Kc 单位 = ‰/RPM；
- 固件 PID 输出域 = "RPM 等效"（1 单位 = 1000/max_rpm ‰）→ **Kp_固件 = Kc × max_rpm/1000**；
- 每帧积分系数 Ki_frame = Kc·Ts/Ti，同样换算；**前馈系数 = 1/K × max_rpm/1000**（乘在 target RPM 上）；
- 禁止口算跨域数值——一律走 step_ident.py 输出。

### 3.4 验证（步骤④）

- A/B/C 消融设计：A=现状基线、B=只改前馈、C=理论全套——**B 与 A 的差 = 前馈贡献；C 与 B 的差 = PID 贡献**，能定位改善来源；
- 指标：90% 上升时间 / 超调% / ±5% 整定时间 / 稳态误差（ab_step.py 自动输出）；
- τc 档位选择：先"稳"档验证收敛，再逐级升到"平衡"；"快"档仅在无负载抖动时用；
- 无线链路不稳时的铁律：**只用 REC/DUMP 机内记录做量化判读**，实时遥测只看趋势。

### 3.5 回写（步骤⑤）

- 固件默认值（main.c 的 spd_param / pid_kp100 / g_ff_gain）更新为最优组 + 注明辨识日期与来源；
- 数据 CSV 与 commit 一起入库（证据链）；本表 §6 记录新参数；
- 在线命令（FF/PID）只改 RAM，**断电即失**——回写才算完成。

## 4. 本工程命令速查

| 命令 | 作用 | 备注 |
|------|------|------|
| `PING` | 握手 | 预期 PONG |
| `STEP <id> <u> <t> [div]` | 开环阶跃 | u=±1000‰, t=100~5000ms, div=遥测分频 |
| `TEL 0/1` | 闭环遥测 10Hz | 弱链路只看趋势 |
| `REC 1/0` + `DUMP` | 机内记录+重放 | 量化判读唯一可靠通道 |
| `FF <val100>` | 前馈在线整定 | 辨识值 100 |
| `P<id> <kp100> <ki100> <kd100>` | PID 在线整定 | RAM 生效 |
| `LA 0` / `L 0` | 关巡线/自动启动 | 台架实验前置 |
| `STOP` | 急停 | 同时关闭全部工具链 |

## 5. 已知坑速查（详调试总结 §17/§18）

| 坑 | 规避 |
|----|------|
| 反馈/驱动符号不配对 → 正反馈飞车 | 符号翻转两侧成对；新电机先小占空验证 |
| 弱链路遥测丢行 | REC/DUMP 机内记录；实时流不用于量化 |
| 爆发式发送丢行 | 逐行 ≥20ms 匀速 |
| OLED 8 页连刷阻塞控制环 | 分页轮转（已固化固件） |
| BT04 掉线/端口漂移 | bt_connect.py 自动发现并存档 |
| 首帧基线误用 | 辨识基线 = 0（静止起步），非首帧采样值 |

## 7. 移植指引（B 层通用化）

换一个工程需要什么：
1. **固件侧最小接口**（B3 契约）：① 开环千分比直通；② 带符号测速；③ STEP/REC/DUMP 三命令（帧格式按契约 v0）；④ 机内记录缓冲（行数×7B）；
2. **PC 侧**：step_capture.py / step_ident.py 直接复用，仅需改 max_rpm 常量与串口参数；
3. **顺序铁律**：带符号反馈 + 抗饱和先行，否则辨识数据无效；
4. 验收标准：第二个工程用同一套流程得到上升时间/超调的可量化改善（本工程基准：150ms/零超调）。
