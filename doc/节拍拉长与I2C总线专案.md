# 节拍拉长专案 — USB 迁移后 ODOM 10Hz 之谜（2026-09-19 开案）

> 状态：✅ **已结案**（2026-09-19 19:05 真机复验：OLED 接稳后 ODOM 恢复 20.00Hz）
> 上游：USB CDC 双链路迁移（见 `双链路仲裁设计文档.md`、`调试总结.md` §23）
> 本专案解决：为什么 USB 链路上 ODOM 只有 10Hz（设计 20Hz）、TEL 5Hz、ITEL 612ms

---

## 0. 结案摘要（2026-09-19 19:05，新会话接手后）

**根因**：`Core/Src/driver/oled_platform_ops.c` 的 OLED 写事务超时 **`OLED_IO_TIMEOUT_MS = 100`**（对比 `i2c_hardware_ops.c` 的 `I2C_TIMEOUT_MS 10`，差 10 倍）。OLED 排线接触不稳/半断电时，每笔写事务吃满 100ms 超时；而显示块在**块首**取基准（`main.c:1069 t_disp = HAL_GetTick()`）造成**自锁**——`now - t_disp ≈ 100 ≥ 100` 立刻又到期 → 显示块**每轮主循环都执行** → pass 被锁死在 100ms → 50ms 控制门每两轮才凑满 → ODOM 10Hz / ATT 5Hz / TEL 5Hz / ITEL ≈ 200ms。

```
OLED 排线接触不稳（用户实测：动排线即黑屏；半断电时 SCL/GND 仍连）
  → I2C2 上 OLED 写事务失败（半断电=总线被拉死；全拔=事务失败）
  → 每笔事务吃满 OLED_IO_TIMEOUT_MS = 100ms
  → 显示块 ≈ 100ms + t_disp 块首赋值 → 下一轮立即到期 → 自锁
  → 主循环 pass ≈ 100ms
  → 控制块 50ms 门每两轮才凑满 → ODOM 20Hz→10Hz、ATT 10Hz→5Hz、ITEL 200→204ms
（同一条 I2C2 上的 MPU6050 读写一并失败 → IMU 全零：伴生现象，不是节拍原因）
```

**判死判活的证据（全部设备侧，不依赖主机侧观测）**：

| 实验 | OLED 异常态 | OLED 正常态（19:05） | 结论 |
|------|------------|--------------------|------|
| `ODOM 1` 帧内 ts 差分 | 恒 100ms（10.00Hz） | **恒 50ms（20.00Hz）** | 帧间隔 = 控制块周期 |
| `REC 1` → `DUMP` 机内记录 tick 差分 | 恒 100ms | — | **设备侧**证明是控制块周期，**不是 USB 发送丢帧** |
| `IRATE 20 / 100 / 1000` 三档 | ITEL 恒 204ms、ODOM 恒 10Hz | ITEL 200ms | IMU 块**不是**成本源 |
| `ITEL 1` 数据 | 陀螺/欧拉全 0 | -29,18,19 / -19,-43,-5 | 总线被拖坏的伴生现象 |
| OLED 全拔（总线悬空） | 仍 10.00Hz | — | 见下"原排除项勘误" |

**原排除项勘误（重要）**：§2 曾以"OLED 整体拔掉后 ODOM 仍 10.2Hz"排除 OLED —— 该推理**逻辑不成立**：OLED *缺席*与半断电同样让写事务失败（同一条 100ms 超时），代价**一样**。硬件侧"拔掉"不能证明"与 OLED 无关"，只有"OLED 恢复正常"才能证伪；本次复验正是后者。**教训：排除嫌疑要看"恢复后是否好转"，不看"移除后是否照旧"——后者对"故障即异常代价"型缺陷无效。**

**修复**：
- **硬件（即效，已验）**：OLED 排线插稳 → 20.00Hz 恢复（2026-09-19 19:05）
- **固件（根治，待实施）**：`OLED_IO_TIMEOUT_MS` 100 → 20ms 量级（正常 128B@100kHz ≈ 11.7ms，须留余量）+ **失败熔断/降级**（连续 N 次失败停刷，不每轮重试）+ 失败计数可见 → **显示器件不允许阻塞控制环**

## 3. 主嫌疑机理：I2C 总线寄生供电（半断电陷阱）—— ❌ 已被否，留档

> **结论（2026-09-19 19:05）**：该机理**不是**根因。真凶是"OLED 写事务超时 100ms + 显示块 100ms 门自锁"（见 §0），与总线是否被寄生供电**无关**——OLED 缺席/半断电/接稳三种状态下，差别只在"写事务是否吃满超时"。以下为当时的推理留档，供对照"为什么猜错"。

**拔线方式 = 只拔 OLED 的 VCC+SDA，SCL/GND 仍连。** 后果链：

```
OLED 失去 VCC → 但 SCL/GND 仍连 → OLED 芯片经 I2C 引脚 ESD 二极管
从总线寄生取电 → 芯片处于半上电病态 → 拉扯总线电平
→ 同一条 I2C2 总线上的 MPU6050 读写开始失败（每次 HAL 超时 10ms）
→ 每轮主循环吃 1~N 个 10ms 超时 → pass 从 ~49ms 膨胀到 100~300ms+
→ 50ms 控制环"每 2 轮才凑满 50ms" → ODOM 20Hz→10Hz、TEL 10Hz→5Hz
→ ITEL 612ms 间隔 = pass≈306ms 的自洽证据
```

**佐证**：
- ITEL 全零行 = main.c 中 `read_gyro_raw` 失败的零值回退路径被触发（MPU 读死）
- 18:16（刚拔线时）euler 还活着 → 18:19 全零 → **渐进劣化**，符合接触/寄生状态漂移
- ODOM ts 间隔"精确 100ms"→"ITEL 612ms"两个观测分别对应 pass=100ms 和 306ms 两个劣化阶段

## 4. 验证执行记录（2026-09-19 18:45~19:05，✅ 已跑完）

> 原"下一步验证"计划（OLED 4 线恢复 + 拔插 USB + 数 ODOM 速率）已执行，**判定 = 仍 10Hz 一侧（阶段 1）→ 转固件侧定位（阶段 2）→ 定位到 OLED 写超时 → 硬件恢复后复验 20Hz 结案**。

| 阶段 | 动作 | 实测 | 判定 |
|------|------|------|------|
| 1 | OLED 只接 GND+SDA（半断电态）；OLED 全拔（悬空态） | 两态均 ODOM **10.00Hz**、IMU 全 0 | 主嫌疑"寄生供电"**否**（拔掉也一样） |
| 2a | `REC 1` → `DUMP` 读**设备侧** tick 差分 | 恒 **100ms** | 是控制块周期，非 USB 丢帧 |
| 2b | `IRATE 20 / 100 / 1000` | ITEL 恒 204ms、ODOM 恒 10Hz | IMU 块**不是**成本源 |
| 2c | 代码核查 `oled_platform_ops.c` | **`OLED_IO_TIMEOUT_MS = 100`** | 与实测 100ms 量级精确吻合 + 显示块 100ms 门自锁 → 锁定 |

**旁路工具（本轮沉淀，可复用）**：① PONG 成簇间隔测 pass 周期；② `REC/DUMP` 读设备侧 tick（不受 USB 发送可靠性影响）；③ ITEL 间隔探"节拍地板"（周期被 pass 顶住时，间隔对 IRATE 不敏感即为地板证据）。
