## 2. P1 级发现（与文档不符或结构性缺陷）

### P1-1 ❌ UART "驱动策略层"在运行时整链不可达 —— ✅ 已处置（2026-09-20，方案 A）

> **处置记录（同日）**：用户拍板方案 A 补回该层。main.c 四处调用点（ISR 重挂 / `uart_send_raw` / init 首挂 / 横幅）改经 `uart_send()`/`uart_receive_IT()` → ops → HAL；平台层顺带修上游残留（超时 1000→100ms 对齐直调口径、UART7@115200→USART2@9600、删 uart_cmd_parser 引用——死层危害实证）；`uart_flush_rx`+`uart_receive` 按 §7 判死删除（P1-7 随批关闭）。验证：编译零新增告警、Flash 55084B（+16B）、nm 确认策略/平台符号入链、八组桩全绿、四组合矩阵过。**真机回归已过（2026-09-20）：烧录拔插自动验证 84.4s + link_regress 13/13 PASS**（详开发跟踪 2026-09-20 条目）。

**现象**：`uart.c`（策略层）4 个对外函数**全部零外部调用**；`uart_platform_ops.c` 的三个函数仅被自身 ops 表引用，而该表也只有 `main.c` 注入、从不经它收发。

```
uart_init / uart_send / uart_receive / uart_receive_IT / uart_flush_rx → 外部引用数 0（逐个实测）
main.c 实际走：HAL_UART_Transmit / HAL_UART_Receive_IT（直调 HAL）
```

**违反**：`代码风格指南 §1.2` 驱动策略层性质（"跨平台通用，void* 句柄 + ops 表"）——该层在 UART 链上**形式存在、路径不存在**；§7.3 判据 1（引用全落在自身文件内）命中。

**连带**：P3 的 `CAR_FEATURE_UART` 之所以只省 992B，是因为真正被门控的是 `main.c` 的 HAL 直调；`uart_platform_ops_stub.c` 属"符号级空壳"（函数本来就不会被调）。

**建议（二选一，需拍板）**：
- **A. 补回该层**：`main.c` 的收发改经 `uart_send()` / `uart_receive_IT()`（ops 注入就此生效，分层名副其实，代价 = 一次函数指针跳转/字节）。
- **B. 承认不走该层**：按 §7 删除 `uart.c` + `uart_platform_ops.*`（含 P3 新增的 stub），HAL 直调留在组装层并在文档写明"UART 链不经策略层，理由=单链路 9600 无移植需求"。
- ⚠️ 现状（保留死层 + 注入死 ops）是**最差选项**：读者会以为存在一层可移植抽象。

### P1-2 ❌ 分层文档的命令链仍是单链路口径

`代码风格指南 §1.1` 与 `§4.1` 均写"命令链：**BT04** → USART2 ISR → ringbuf → 解析 → 应答"，而实现已是 USB CDC 主链 + BT04 备链 + 指挥权门控。双链路仲裁已收口（P3），分层模型未跟随。

**违反**：§1.1 数据链总览（架构事实源）。**建议**：补为"USB CDC / USART2 两条输入 + ringbuf ×2 + 指挥权门控"，并链接仲裁文档 §3。

### P1-3 ❌ §4.4「ringbuf 消费：主循环 while 一次清空」与 P3 时间片冲突

实现为每链路每轮**最多 `LINK_BYTE_BUDGET`(64) 字节**（时间片封顶，防单链路饿死对链），突发 200B 时跨轮消费完。

**违反**：时序约束表与代码不一致（该条的原意是"禁止逐字节消费导致丢帧"，与分片并不冲突，但字面已不成立）。**建议**：订正为"每链路每轮 ≤ LINK_BYTE_BUDGET 字节，分片跨轮消费至清空；禁止逐字节消费（调试总结 §9）"。

### P1-4 ❌ `doc/工程文档.md` 不含 USB（引脚/初始化权威缺口）

全文档对 `PA11/PA12/USB CDC/0483:5740/USB_DEVICE` **零命中**，而 USB 已是上位机主链。**违反**：指南 §6 交叉引用（工程文档 = 引脚/协议/初始化流程权威）。**建议**：补 USB 小节（引脚、VID/PID、初始化顺序、烧录后拔插枚举坑）。

### P1-5 ❌ OLED 页 7 的"页分配权威"未回写（义务 4）

`工程文档.md:114` 仍写 `页7 = CAL:x% / LINE 状态`；实现已是"链路状态 + 健康计数"（`L:<owner> USB:ON|OFF U:<秒>`，异常态 `E<n> O<n> FZ`）。巡线剔除后页 7 被复用，但**未按义务 4 在权威文档登记**。

### A.3 结构判读（P2-9 的依据）

- **胖在"协议执行"（26.7%），不是决策/控制**：控制块 + 显示块合计仅 ~280 行，与脑干模型吻合（节拍/仲裁/安全/呈现）——组件化收干净的是这部分。
- 因此若做 P2-9，**唯一有效动作 = 把 39 个命令执行分支抽出**（同文件内按命令族抽静态函数，不改层位、不改语义），预计可挪走 ~350 行；动控制块/显示块收益极小。
- 配置表/全局状态（17.4%）在标定集中（3②）后已收敛为"装配引用"，属合理体量。
