## 一、控制环节清单

系统中真正的闭环回路只有 **2 个**（巡线决策环 + 速度环，级联结构），其余为开环执行链或感知支路。

| 编号 | 环节 | 类型 | 周期 | 传感器 | 算法 | 执行器 | 反馈量 | 状态 |
|------|------|------|------|--------|------|--------|--------|------|
| L1 | 速度环 ×2 | 闭环（内环） | 50ms | TIM2/TIM3 增量编码器 PPR=1466 | 增量式 PID（Kp=0.24 Ki=0.13 Kd=0）+ 前馈 0.3×目标 | TB6612 → PWM 20kHz | 实测 RPM（\|ΔN\|/dt，取绝对值） | 跑通，参数未精调 |
| L2 | 巡线环 | 闭环（外环，级联于 L1） | 50ms | 5 路灰度 PB3-PB7 二值采样 | PD（Kp=6 Kd=2）+ 三层阻尼 + 四状态机 | 差速目标 spd_target[2]/spd_dir[2]（写入 L1 设定值） | 车体-黑线相对位置（物理量） | 跑通，实车整定待做 |
| L3 | 转向链 | **开环** | 事件驱动 | 无 | 行程钳位 + 域换算（steering 组件） | 舵机 PWM 50Hz（PB8） | 无 | 跑通 |
| L4 | 姿态感知链 | 感知（未构成控制） | 100ms | MPU6050（I2C2） | Mahony 滤波 + 运行中零偏跟踪 | 无（仅 OLED 显示 + 校准门控自动启动） | — | 跑通 |
| — | 平衡环 | 不存在 | — | — | — | — | — | 两轮差速车无平衡需求 |

级联关系：L2（位置外环）→ spd_target/spd_dir → L1（速度内环）→ PWM。外环输出即内环设定值，标准 cascade 结构；两环同帧（50ms）顺序执行，外环输出当帧即被内环消费，**级联间零额外延迟**，这是当前设计的一个优点。

## 二、各回路信号链路

### 2.1 L1 速度环（每电机一条，共 2 条）

| 环节 | 实现与要点 |
|------|-----------|
| 采集 | 编码器 16 位计数器帧差，±30000 回绕校正（50ms 内最大 ΔN≈390，远离回绕，安全）；dt 用实际 tick 差计算，对主循环抖动有补偿 |
| 测速 | RPM = \|ΔN\|×60/(dt×PPR)；分辨率 0.82 RPM/count（@50ms）；**取绝对值，方向信息丢失**（方向由 spd_dir 单独表达） |
| 控制律 | 增量式 PID；输出限幅 ±319（PID 内部）+ 前馈 ff=0.3×目标（PID 外部叠加）后再次钳位 [0,319] |
| 执行 | motor_bridge_set_speed_rpm → Motor::set_speed_rpm → 死区判断（5%×319≈16 RPM，低于则 protocol.stop() 滑行）→ map 到千分比 → TB6612 |
| 特殊语义 | 目标<1.0 RPM → pid_reset + 物理刹停（0速=停）；spd_dir==0（内侧轮）→ 冻结 PID + 刹停 + 重置测速基准 |

### 2.2 L2 巡线环（决策层）

| 环节 | 实现与要点 |
|------|-----------|
| 采集 | 5 路灰度直调 HAL_GPIO_ReadPin（架构评审 C2违例），50ms/帧二值 |
| 信号处理 | 加权位置 (-2s1-s2+s4+2s5)/Σ ∈ [-2,2] → EMA 平滑（新 0.6 / 旧 0.4，等效约 1.7 帧平均） |
| 控制律 | PD：corr=(Kp·pos+Kd·d_pos)×g_decay；叠加三层阻尼——回中反向阻尼（2 帧）、过冲衰减（换向即 g_decay×0.5）、迟滞确认（连续 2 帧） |
| 决策 | 四状态机：FOLLOW → LINE_EXIT（刹车 200ms）→ TURNING（单轮支点转弯，≥500ms 且见线回归）→ 回正冷却 800ms；丢线 → SEARCH（800ms 摆扫，4s 超时停车） |
| 输出 | 差速：target0=base+corr、target1=base-corr，下限钳 0 |
| 时序参数 | 直角/转弯全用**时间**驱动（200ms/500ms/800ms）；编码器计程接口（straight_cnt/turn_cnt）预留未接，update() 传入的 enc0/enc1 为死参数 |

### 2.3 L3 转向链（开环，范本级实现）

命令角 → steering 组件钳位（机构行程 [-115,-65]）→ +135° 安装偏置 → servo_bridge → Servo → PWM 50Hz。三级钳位各管各的域（组件/Servo/协议），无任何反馈（舵机内部电位器闭环不暴露给主控）。作为开环链是合理的，但意味着**前轮定位误差、舵机虚位都无法在车上补偿**。

### 2.4 L4 姿态感知链

MPU6050 → I2C2 → 50 次采样零偏校准 → Mahony（Kp=0.5, Ki=0）+ 静止检测动态零偏跟踪 → 欧拉角 → OLED。100ms 更新（10Hz），DLPF 配 0x06（5Hz 带宽）。当前仅显示 + 校准完成门控自动启动巡线，**不参与控制**。

## 三、数据流向与耦合关系

### 3.1 模块依赖

- **垂直链**：main.c（组装层）→ line_follower（决策）→ [全局变量] → PID（common）→ motor_bridge → Motor → TB6612Protocol → pwm/usergpio（驱动）→ HAL。命令链（txt_cmd）与显示链（oled_bridge）经组装层正交接入。
- **违例一处**：line_follower.c 直调 HAL_GPIO_ReadPin（main.h 的 OUT1~OUT5），未走注入接口——已知问题（评审 C2），main.c 页3 显示灰度也重复直调。

### 3.2 耦合点分析

| 耦合点 | 形式 | 评估 |
|--------|------|------|
| spd_target[2] / spd_dir[2] | main.c 静态全局，巡线写、命令处理写、PID 段读 | **三写一读的隐式全局耦合**，是两环唯一交接面。接管权仲裁分散在三处状态（g_enabled、spd_target、spd_dir），STOP 必须同时清三处——已踩坑（"车复活"）。建议收敛为单一"控制权持有者"结构 |
| 接管权 | line_follower_enable + 每条手动命令先 enable(0) | 靠约定而非机制，新增命令容易漏（目前每条都记得写，无编译期保证） |
| 帧时序 | 巡线、测速、PID 同帧顺序执行；OLED 8 页 + IMU 在 100ms 帧串行执行 | 控制链对显示链**时间上互斥**：I2C 8 页（超时 10ms/页）与串口阻塞发送（9600bps，20 字节≈21ms）都发生在主循环内 → 控制帧周期抖动可达数十 ms。测速有 dt 补偿，PID 有 dt 参数，但 EMA、迟滞计数器、阻尼帧数（brake_cnt=2）均按"帧"计数、无 dt 感知 → 抖动直接扭曲阻尼时序 |
| ISR→主循环 | UART 中断只 ringbuf_write，业务全在主循环 | 符合铁律，无耦合风险 |

## 四、控制周期、采样频率与信号处理核算

| 量 | 数值 | 推导与含义 |
|----|------|-----------|
| 控制帧 | 50ms（20Hz） | 速度环带宽须远低于奈奎斯特 10Hz，实际 PID 增益下等效带宽约几 Hz，量级合理 |
| 编码器测速分辨率 | 0.82 RPM/count | 30 RPM 时每帧 ΔN≈37，量化噪声 ±2.7%；10 RPM 时 ΔN≈12，±8%；低速时噪声占比显著上升 |
| 灰度帧率 | 50ms/帧 | 30 RPM ≈ 10.3 cm/s 车速，每帧位移约 5mm，小于传感器间距，采样足够 |
| 迟滞确认延迟 | 2 帧 = 100ms | 偏离/回中确认的固有滞后，是三层阻尼的一部分 |
| EMA 时间常数 | 约 33ms（α=0.6@50ms） | 平滑与滞后的折中，量级合适 |
| IMU 更新 | 100ms（10Hz），DLPF 5Hz | 仅够显示；若二期做航向/平衡闭环须 ≥100Hz + 定时器驱动采样 |
| 舵机 PWM | 50Hz | 舵机本身响应 ~100-200ms，控制帧无需更快 |

## 五、问题清单（分级）

### P0 — 影响控制正确性，建议先修

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 1 | **增量式 PID 输出限幅不回写内部状态**：prev_output 存的是未钳位值，随后主循环叠加前馈再钳位 [0,319] 也同样不回写 | pid.c 增量式实现 + main.c PID 段 | 长时间大误差（如死区内、起步堵转）下内部输出无界累积（windup），误差反向后要"消化"很久才能退出限幅 → 超调、响应迟钝。这是当前调参"怎么调都怪"的最可能根因 |
| 2 | **测速取绝对值丢方向**：actual_rpm=\|ΔN\| | main.c 测速段 | 车轮短暂倒转（过冲回修、被碰、刹车滑行反转）时反馈仍读"正转"，控制器误判转速正常 → 差错无法纠正甚至正反馈。速度环反馈应带符号，方向语义由符号统一表达，spd_dir 只用于目标侧 |

### P1 — 影响性能与安全

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 3 | **Motor 死区语义冲突**：目标<16 RPM 时 set_speed_rpm 调 stop()（滑行），与上层"0速=brake"语义不一致；差速修正低侧轮可能掉进死区 | motor.cpp | 左右不对称响应、低速极限环振荡；PID 看到目标 30 实测 0 持续积分（叠加上 P0-1） |
| 4 | **转弯/刹车全靠时间参数**，编码器计程接口预留未接（enc0/enc1 死参数） | line_follower.c | 电池电压下降、地面摩擦变化时转弯角度漂移；单轮支点转弯尤其敏感 |
| 5 | **无命令看门狗**：蓝牙断链后车保持最后目标一直跑；帧无 CRC | main.c 命令段 | 无线调试最大安全隐患。建议最后有效命令 500ms~1s 超时自动刹停（调试期可开关） |
| 6 | **串口阻塞发送**：ack/巡线诊断 tx_raw 在 9600bps 下每次最长 ~21ms，且巡线事件高频 | main.c | 50ms 帧抖动，EMA/阻尼的"帧"语义失真。建议改 TX DMA（中断+ringbuf 已有对偶方案）或降诊断频率 |
| 7 | OLED 8 页 I2C 串行刷新与控制链互斥 | main.c 100ms 段 | 同 #6，帧抖动来源之一（显示刷新与命令解析分离原则未完全落实） |

### P2 — 已知/低优先

- 灰度直调 HAL（评审 C2，已有治理计划）；line_follower enc 参数死（随 #4 一起处理）。
- 位置式积分分离判据不对称（只查上界）——当前用增量式不受影响，切换模式时会踩。
- 增量式首拍微分踢（pid_reset 后首帧 d_term=kd·e/dt）——当前 Kd=0 无影响，加 D 项时注意。
- EMA/迟滞/阻尼按帧计数，隐含固定周期假设（与 P1-6/7 相关）。
- firewater_send（VOFA+ 帧发送）已实现但 0 调用——**是现成的调试基建，可复用**。

## 六、改进方向

1. **修 P0-1（抗饱和）**：钳位后回写 prev_output（clamping anti-windup），主循环外层钳位值也回写；这是零成本、收益最大的单点修改。
2. **修 P0-2（带符号测速）**：ΔN 直接带符号换算 RPM；确认 M1/E2 软件取反后符号约定一致（AGENTS.md 坑表已列，改动前核对）。
3. **前馈标定替代拍脑袋 0.3**：稳态下记录"目标 RPM → 稳态千分比"映射，前馈给准后 PID 只修扰动，积分负担和 windup 风险都下降。
4. **测速加轻量滤波**：2~3 帧滑动平均或可调一阶低波（0.82 RPM/count 噪声 × Ki=0.13 是当前输出抖动来源之一）。
5. **转弯改编码器计程**：接通 straight_cnt/turn_cnt，直角弯按 ΔN 判进度，时间参数退化为超时保护。
6. **看门狗 + 帧校验**：调试期安全网，AGENTS TODO 已列 CRC。
7. **串口 TX 改 DMA**：消除控制帧抖动的最大单点。

## 七、对"闭环调试软件开发"的需求输入（下一步）

现有基建：上行仅横幅/ack/巡线事件，**无周期遥测**；下行已有 GK/GD/GS/PID/PID SWAP 在线调参命令；firewater_send（VOFA+ float 帧大端+校验）已写好未启用。建议调试软件按以下优先级建设：

1. **按需遥测命令（最高优先）**：新增命令开启周期上报，每控制帧发一行：tick + 每电机 (target, actual_rpm, out_0E3, dir) + 巡线 (pos_raw, pos_ema, corr, state)。带宽核算：9600bps≈960B/s，压缩后每帧约 40B×20Hz=800B/s 勉强够；**整定期间建议切回 115200**（BT04 透传波特率可配）或降为 10Hz。带遥测后 P0 问题（windup、丢方向）在曲线上会直接显形。
2. **阶跃测试命令**：固定参数下发目标阶跃（0→N RPM），遥测同步记录，一次实验得到完整响应曲线，替代手动 M 命令+人眼看 OLED。
3. **复用/启用 firewater_send**：PC 端直接接 VOFA+ 看曲线，零上位机开发成本；自研上位机可后置。
4. **遥测与控制帧同源**：上报点放在 PID 段末尾，保证 target/actual/out 三元组是同一帧的快照，避免时间对不齐。
5. **参数组命令**：现有 PID SWAP 可扩展为"参数组 A/B + 一键切换"，配合阶跃测试做对比实验。

## 八、结论

- 级联结构（位置外环+速度内环）选型正确，同帧执行消除了级联延迟；steering 组件的注入式写法是执行链的范本。
- 当前最大的两个正确性缺陷都在**速度环反馈/控制器内部**：增量式 PID 抗饱和缺失、测速丢方向——它们会让整定工作事倍功半，建议在任何新一轮 PID 整定**之前**先修。
- 帧抖动（串口/OLED 阻塞）当前被 dt 补偿部分掩盖，但巡线层的帧计数类机制暴露在抖动下；TX DMA 化后一并解决。
- IMU 链现状是感知而非控制，二期若做航向闭环须重做采样时序（≥100Hz、定时器驱动），本次无需动。
