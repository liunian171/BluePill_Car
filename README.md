# BluePill_Car — STM32F103 两轮差速循迹小车

> **本 README 的核心是 §3「串口通信接口」**——下位机（STM32）与上位机（PC / 手机 APP）之间
> 的完整数据接口约定，供上位机程序开发与联调直接照此实现。
> 工程内部架构与开发规范见 [`AGENTS.md`](AGENTS.md)，文档全索引见 AGENTS.md §六。

**当前状态**：驱动链全通（电机 / 编码器 / IMU / OLED / 串口 / 灰度）；执行栈两侧组件已组件化
（`steering` 转向、`speed_loop` 速度环）；桥接层家族契约已落地；闭环调参工具链可用（阶跃辨识 + 遥测 + 机内记录）。
巡线状态机已实现集成，实车整定未完成。

## 1. 硬件与工程概况

| 项 | 值 |
|----|----|
| 主控 | STM32F103C8T6（BluePill），72 MHz（HSE 8M + PLL×9），Flash 64 KB / RAM 20 KB |
| 电机 | TB6612 ×2 通道，TIM1 PWM 20 kHz（PA8 / PA9），方向 PB12–PB15 |
| 编码器 | TIM2 / TIM3 编码器模式，**PPR = 1466**（实测） |
| 轮组 | 车轮周长 20.5 cm，max_rpm = 319（实测标定） |
| 巡线 | 5 路灰度 PB3–PB7，二值采样 50 ms/帧 |
| IMU | MPU6050（I2C2 0x68），Mahony 融合 + 静止漂移补偿 |
| 显示 | SSD1315 OLED（I2C2 0x3C），128×64 |
| 舵机 | TIM4_CH3（PB8），50 Hz PWM |
| 串口 / 链路 | **USB CDC（主链，0483:5740）** + **USART2（PA2 = TX / PA3 = RX）→ BT04 经典蓝牙 SPP（备链，9600）**，两条链路跑同一套协议（详 §3） |

## 2. 构建与烧录

工具链：STM32CubeCLT（ARM GCC / CMake / Ninja / CubeProgrammer）。

```bash
cmake -S . -B build/Release          # 配置（新增源文件后必须重跑：源文件用 GLOB 收集）
cmake --build build/Release          # 编译
```

```bash
# 烧录（SWD，烧完自动复位）
STM32_Programmer_CLI.exe -c port=SWD -w build/Release/BluePill_Car.elf 0x08000000 -rst

# 或者一步到位（编译 + 烧录，见 flash.bat）
./flash.bat
```

> 务必用 **Release**（Debug `-O0` 会超出 64 KB Flash）。注意 CMake 用 GLOB 收集源文件，
> **新增 `.c/.cpp` 后要重新执行一次 configure**，否则链接会报 undefined reference。
> 2026-09-19 瘦身批次后当前占用 **Flash 55068B / 84.03%**（`-flto` 试用因真机 HardFault 已回退，详 `doc/调试总结.md` §25）。

**功能/链路编译开关**（`Core/Inc/car_config.h`，单一真值源；**改宏后必须重新 configure**）：

| 宏 | 默认 | =0 的效果 |
|----|:---:|-----------|
| `CAR_FEATURE_LINE_FOLLOWER` | 0 | 巡线状态机编译期剔除（空壳替换 `line_follower_stub.c`） |
| `CAR_FEATURE_USB` | 1 | USB 链路接线整体下线（ringbuf 不消费 / 判活恒假 / 仲裁固定 UART） |
| `CAR_FEATURE_UART` | 1 | UART 链路接线整体下线（不开中断接收 / 发送 no-op / 平台 ops 换空壳） |

> 三个宏**只允许**作用于 CMake 源文件列表与组装层接线（`main.c` 链路开关门控 + `app_wiring.c` 装配配置）；组件层/桥接层/其余 app_* 模块禁止 include。
> 链路双 0 会被 CMake 直接拒绝。四组合验证脚本：`bash tools/car_cfg_matrix.sh`。

**整车标定表**（同一文件的 `§整车标定` 段，2026-09-19 集中）：PPR / 编码器计数模值 / 轮周长 / 轮半径 / 轮距 /
电机上限与 PWM 频率 / M1 方向镜像对 / 速度环 PID 与前馈 / IMU 安装方向 / 舵机行程与直行位 /
三处节拍 / 巡线初值 —— 数值**只在这里出现一次**，组装层在配置结构体初始化处引用。
改数值**不需要重新 configure**（与开关宏不同），但必须重新编译烧录 + 走真机回归
（`python tools/link_regress.py`）。规则见 [`doc/代码风格与模块衔接指南.md`](doc/代码风格与模块衔接指南.md) §4.5。

PC 侧单元测试桩（无需硬件）：


## 3. 串口通信接口（下位机 ↔ 上位机）

### 3.1 物理层参数

下位机提供**两条并列的命令链路**，跑**同一套协议**（同一解析器、同一应答格式 → 上位机换链路不改代码）：

| 项 | **USB CDC（主链，推荐）** | **UART / BT04（备链）** |
|----|------------------------|------------------------|
| 端侧表现 | 虚拟串口，`VID:PID = 0483:5740`（设备管理器："USB 串行设备"） | USART2 → BT04 经典蓝牙 SPP（PC 侧为一个 COM 口，**端口号随配对漂移**，历史 COM15→14→12） |
| 波特率 | 不适用（USB FS bulk，与串口波特率无关） | **9600**（改固件须同步改模块 AT 配置） |
| 帧格式 | — | **8N1**，无流控 |
| 实测链路能力 | 单命令往返 **0.2 ms**、突发 40 条零丢；带宽不受 9600 约束 | **960 B/s**；命令往返受 BT04 打包节拍支配（≈15.5 ms 整数倍），高行速率会成块丢行 |
| 判活信号 | 枚举完成 + 终端应用**拉 DTR**（打开串口即拉） | MCU 无法感知 SPP 连接态 → 以"距最近收字节的秒数"近似（OLED 页 7 `U<秒>`） |
| 烧录后 | **软复位不重枚举**（打开报错 31）→ **需拔插一次 USB**；用 `tools/flash_flow.py` 可自动化等待+验证 | 无此问题（BT04 重连后端口号可能变，用 `tools/link_probe.py` 重新发现） |

- 引脚：USART2 = PA2(TX) / PA3(RX)；USB = PA11(D−) / PA12(D+)，DP 侧 1.5 k 上拉
- 默认**两条都启用**；可用 `Core/Inc/car_config.h` 的 `CAR_FEATURE_USB` / `CAR_FEATURE_UART` 编译期关掉任一条（详见 §3.11 与 `doc/双链路仲裁设计文档.md`）
- 探测两条链路的当前状态：`python tools/link_probe.py`（自动发现 + 归类 + `PING` 探测 + 报 owner）

### 3.2 数据流总览

**上行（下位机 → 上位机）四类**：

| # | 类型 | 触发 | 默认 |
|:--:|------|------|:---:|
| ① | 开机横幅 `UART2 Ready` | 复位后一次 | 常开 |
| ② | **命令应答**（文本） | 收到命令即回 | 常开 |
| ③ | **遥测**（CSV / 二进制 ODOM） | 按需开启：`TEL 1` / `STEP` / `DUMP` / `ODOM 1` | **关** |
| ④ | 巡线诊断事件（文本） | 巡线状态机跳转时 | 仅巡线使能时 |

**下行（上位机 → 下位机）两类**：文本命令（§3.7）、二进制帧（§3.8）。两者可混用，互不干扰，**任一链路都可发**（但受指挥权门控，见 §3.2.1）。

> ⚠️ **默认状态下固件不上报任何周期数据**——不打开遥测就只会看到命令应答。
> 想看 IMU 欧拉角 / 编码器计数 / PID 参数，需**看 OLED 屏**（页 0–7）或按 §3.5 打开遥测。

### 3.2.1 双链路指挥权（owner）与 failover

两条链路同时在线时，**只有一条持有指挥权（owner）**——上电默认 USB：

| 行为 | 语义 |
|------|------|
| **应答/遥测路由** | **按命令来源回**（谁发命令，应答与遥测就回谁）——注意这与"owner"是两件事 |
| **运动命令门控** | 非 owner 链路的命令被拒：文本回 `BUSY:USB` / `BUSY:UART`，二进制帧同（仅心跳 `0xF0` 放行） |
| **安全例外** | `STOP` 与 `LINK ?` **不经门控**，任一链路直达 |
| **切换** | `LINK USB` / `LINK UART` 三语义合一（接管 / 让出 / 抢回，目标=自己即无操作）；调参会话（`STEP/TEL/REC/ODOM/ITEL` 任一激活）期间拒绝切换，回 `BUSY:SESSION` |
| **自动 failover** | USB 失活（枚举掉 / 应用关掉 DTR）且 owner=USB → 自动切 UART，并向 owner 链路广播 `USB LOST -> UART TAKEOVER` |
| **恢复不抢回** | USB 重新上线时**只广播** `USB READY`，owner 不变 —— 需显式 `LINK USB` 才切回（避免端口一被打开就指挥权跳变） |
| **看门狗** | `WD <ms>` 只盯 **owner** 链路的输入；非 owner 链路的字节不喂狗 |
| **单链路编译模式** | `car_config.h` 编译期关掉某条链路时，仲裁固定在该链路；对已关闭链路的 `LINK` 请求回 `LINK:OFF` |

查询当前 owner：`LINK ?` → `OWNER:USB` / `OWNER:UART`（OLED 页 7 的 `L:` 字段同源）。

### 3.3 上行①：开机横幅

**仅在 UART 链路上**、复位后立刻发送一次，可用来**探测端口 / 确认固件在跑**：

```
UART2 Ready\r\n          （13 字节）
```

> USB 链路**没有横幅**（枚举与复位时序无关，横幅会发丢）→ USB 侧的"活着"判据是
> `PING` → `PONG`（或用 `tools/flash_flow.py --verify` 自动完成）。
> 若 `car_config.h` 的 `CAR_FEATURE_UART=0`，UART 被编译期关闭，横幅也不会出现。

### 3.4 上行②：命令应答（文本）

每条（被识别的）命令都会回一行文本，行尾 `\r\n`。**这是上位机确认命令是否被执行的唯一依据**。

| 触发命令 | 应答格式 | 示例 |
|---------|---------|------|
| `PING` / 帧 `0xF0` | `PONG\r\n` | |
| `STOP` | `STOP OK LINE OFF\r\n` | |
| `M0 <rpm>` / `M1 <rpm>` | `M<id>:<rpm>RPM\r\n` | `M0:60RPM` |
| `MS <rpm>` | `MS:<rpm>RPM\r\n` | |
| `B0` / `B1` | `M<id>:BRAKE\r\n` | |
| 帧 `0x03` | `M<id>:BRAKE\r\n` | |
| `P<id> …` （单电机） | `PID<id>:<kp100> <ki100> <kd100>\r\n` | `PID0:87 40 0` |
| `<kp100> <ki100> <kd100>`（双电机） | `PID ALL:<kp100> <ki100> <kd100>\r\n` | |
| `S`（交换增益） | `SWAP:M0 <kp> <ki> <kd>  M1 <kp> <ki> <kd>\r\n` | ×100 整数 |
| `L 0/1` | `LINE:ON\r\n` / `LINE:OFF\r\n` | |
| `LA 0/1` | `LA:<0/1>\r\n` | |
| `GK/GD/GS <f>` | `GK:<int>.<dec1>\r\n` 等 | `GS:30.0` |
| `GI` | `GI:<0/1>\r\n` | 灰度反相标志 |
| `GC/GT <int>` | `GC:<n>\r\n` / `GT:<n>\r\n` | |
| `E<id> <ppr>` | `PPR<id>:<ppr>\r\n` | |
| `SV <deg>` / `SV+` / `SV-` | `SV:<角>.<dec1>\r\n` | `SV:-90.0` |
| `SL/SR/SC <deg>` | `S<L/R/C>:<角>.<dec1>\r\n` | `SC:-95.0` |
| 同上但入参越限 | 尾部追加 ` BAD` | `SL:-200.0 BAD` |
| `STEP …` 启动成功 | `STEP GO <id> <u> <t> <div>\r\n` | |
| 阶跃测试结束 | `STEP END\r\n` | 到时自动刹停 |
| `STEP` 参数非法 / 忙 | `STEP BAD\r\n` / `STEP BUSY\r\n` | |
| `TEL 0/1` | `TEL:<0/1>\r\n` | |
| `FF <val100>` | `FF:<int>.<两位小数>\r\n` | `FF:1.00` |
| `FF` 越限 | `FF BAD\r\n` | |
| `REC 0/1` | `REC:<0/1>\r\n` | |
| `DUMP` | `DUMP <n>\r\n` … n 行数据 … `DUMP END\r\n` | 见 §3.5 |
| `ODOM 0/1` | `ODOM:<0/1>\r\n` | 上位机里程计帧开关 |
| `WD <ms>` | `WD:<ms>\r\n`（越限 `WD BAD`） | 0=关闭 |
| `ITEL 0/1/2` | `ITEL:<mode>\r\n` | IMU 遥测模式 |
| `IGAIN <kp> <ki>` | `IGAIN:<kp> <ki>\r\n` | Mahony 增益（×100 整数） |
| `IDRIFT 0/1` | `IDRIFT:<0/1>\r\n` | 漂移补偿开关 |
| `IRATE <ms>` | `IRATE:<ms>\r\n` | 20~1000 |
| `ICAL` | `ICAL:GO\r\n` | 触发重新零偏校准 |
| `LINK ?` | `OWNER:USB\r\n` / `OWNER:UART\r\n` | 查询指挥权 |
| `LINK USB` / `LINK UART` | `LINK:USB OK\r\n` / `LINK:UART OK\r\n` | 切换成功（目标==当前也算 OK） |
| `LINK …` 但调参会话激活 | `BUSY:SESSION\r\n` | 会话锁拒绝切换（`STOP` 仍生效） |
| `LINK …` 但目标链路被编译期关闭 | `LINK:OFF\r\n` | 单链路模式，该链路不存在 |
| 非 owner 链路的运动命令 | `BUSY:USB\r\n` / `BUSY:UART\r\n` | 指挥权门控；`STOP`/`LINK ?` 不受门控 |
| 未识别的文本 | `?\r\n` | |
| 未识别的帧 | `?\r\n` | |

> **异步行**（不是应答，随时可能插入，见 §3.2.1）：`USB LOST -> UART TAKEOVER`、
> `USB READY`、`WD TIMEOUT STOP`，以及巡线诊断事件（§3.6）。
> → 上位机**不要假设"下一行就是自己命令的应答"**，按行前缀分类解析。

> ⚠️ **浮点应答只有 0.1 精度**：固件禁用 `%f`（nanospec 无浮点 printf），改为"整数部 + 十分位"拆分。
> 十分位四舍五入后**饱和在 9**（如 −90.97 显示 `-90.9`，**不会进位**成 −91.0）。
> 需要更精确的读数请用二进制帧或机内记录，别把文本应答当高精度数值使用。

### 3.5 上行③：遥测 CSV

三种遥测**共用一套"逗号分隔 + `\r\n` 行尾"的文本格式**，上位机按列数区分。

#### (a) 开环阶跃遥测 —— `STEP` 期间自动开启

```
t_ms,rate_0E3,rpm_x10
123,600,1302
223,600,1784
```

| 列 | 含义 | 单位 |
|:--:|------|------|
| `t_ms` | 自阶跃开始的毫秒数 | ms |
| `rate_0E3` | 下发的千分比指令（±1000 = ±100.0%） | 0.1% |
| `rpm_x10` | 电机实测转速 × 10（**带符号**） | 0.1 RPM |

- 频率：默认 **20 Hz**（50 ms 一行）；`STEP <id> <u> <t> 2` 的第 4 个参数可降为 10 Hz（弱链路防丢行）
- 生命期：`STEP GO` 起 → `STEP END` 止（到时自动刹停并关闭）
- 用途：FOPDT 模型辨识（`tools/step_ident.py`）

#### (b) 闭环遥测 —— 需 `TEL 1` 开启

```
tick,tgt0,rpm0,tgt1,rpm1
223313,30,31,0,0
```

| 列 | 含义 | 单位 |
|:--:|------|------|
| `tick` | 下位机 `HAL_GetTick()` 毫秒计数 | ms |
| `tgt0` / `tgt1` | M0 / M1 的**带符号目标转速** | RPM |
| `rpm0` / `rpm1` | M0 / M1 的**带符号实测转速** | RPM |

- 频率：**10 Hz**（100 ms 一行），与 50 ms 控制环解耦（2 分频）
- **同帧快照**：五个字段取自同一次控制节拍，可直接做"目标 vs 实际"对照
- `TEL 0` 或 `STOP`（急停联动）关闭

#### (c) 机内记录重放 —— `REC 1` 记录，`DUMP` 重放

```
DUMP 128
223313,30,31,0,0
223363,30,30,0,0
...
DUMP END
```

- `REC 1`：以 **20 Hz** 把闭环数据写入下位机 RAM（128 条 ≈ 6.4 s，开记录即清空缓冲）
- `DUMP`：把缓冲以 **20 ms 一行**匀速重放（格式与 (b) 完全相同，可重复执行以补全丢行）
- 用途：对抗蓝牙链路丢行——先机上记录，再慢速重放，保证数据完整

#### (d) IMU 姿态遥测 —— 需 `ITEL 1` 开启（2026-09-15 新增）

```
tick,gx10,gy10,gz10,roll10,pitch10,yaw10,stable,driftz100
340000,2,0,92,0,0,175,1,80
```

| 列 | 含义 | 单位 |
|:--:|------|------|
| `tick` | 下位机毫秒计数 | ms |
| `gx10/gy10/gz10` | **原始**陀螺仪角速度 ×10（未减零偏/补偿，诊断列） | 0.1 °/s |
| `roll10/pitch10/yaw10` | Mahony 融合欧拉角 ×10 | 0.1 ° |
| `stable` | 静止标志（\|a\|−1g<0.05g；**旋转中恒为 1 = 漂移补偿误吸收窗口**） | 0/1 |
| `driftz100` | Z 轴漂移补偿当前值 ×100 | 0.01 °/s |

- 频率：IMU 更新节拍（`IRATE`，默认 100ms）**2 分频** = 默认 5Hz，≈45B/行 ≈ 23%@9600
- **模式 2 = VOFA+ FireWater**：行 `gx,gy,gz,roll,pitch,yaw,driftz`（逗号分隔+`\r\n`），7 通道
  均为真实物理量（°/s 与 °，两位小数）——VOFA+ 选 FireWater 协议免配置直出曲线；
  通道 0-6 依次为：陀螺 xyz（原始含零偏）/ 欧拉角 xyz / Z 轴漂移补偿。与模式 1 **二选一**
- 用途：IMU-1 yaw 失真专案 E 系列实验（`IDRIFT 0` / `IGAIN 0 0` / `IRATE 50` 二分定位），
  配套工具 `tools/imu_turn_test.py`（90° 转角协议化：跟随角/回落量/静置漂移三指标 + 陀螺侧积分交叉验证）

### 3.6 上行④：巡线诊断事件

巡线功能使能（`L 1`）时，状态机每次跳转发一行文本（行尾 `\r\n`）：

| 消息 | 含义 |
|------|------|
| `LINE:LOST` | 丢线，进入 SEARCH 摆扫 |
| `LINE:FOUND` | 重新找到线 |
| `LINE:SRCH` | SEARCH 摆扫中 |
| `LINE:CRN L` / `LINE:CRN R` | 判定左 / 右直角弯 |
| `LINE:OVERSHOOT` | 过冲衰减触发 |

> 这些是**诊断事件**（非周期），用于排查巡线行为；不占用命令应答通道。

### 3.7 下行①：文本命令

- 行尾：`\n` 或 `\r\n` 均可（固件过滤 `\r`）；单行最长 19 字符
- 大小写敏感；数值支持负数与小数

| 命令 | 参数 | 说明 |
|------|------|------|
| `PING` | — | 心跳 |
| `STOP` | — | **急停**：双轮刹停 + 关巡线 + 关自动 + 舵机回直行位 + 关所有调参工具 |
| `M0 <rpm>` / `M1 <rpm>` | 带符号 RPM | 单轮目标转速（**手动指令会取出巡线接管权**） |
| `MS <rpm>` | 带符号 RPM | 双轮同步 |
| `B0` / `B1` | — | 单轮刹车（清目标 + 释放 PID + 物理刹停） |
| `P<id> <kp100> <ki100> <kd100>` | id = 0/1 | 单电机 PID 增益（×100 整数） |
| `<kp100> <ki100> <kd100>` | 三个整数 | 双电机 PID 增益 |
| `S` | — | 交换 M0/M1 的 PID 增益（同时回显两侧真值，可作读回用） |
| `L 0/1` | — | 巡线使能 |
| `LA 0/1` | — | 巡线自动启动（IMU 校准完成后自动开巡线） |
| `GK/GD/GS <f>` | 浮点 | 巡线 Kp / Kd / 基础速度 |
| `GI` | — | 灰度传感器反相开关（切换后回显当前值） |
| `GC <int>` / `GT <int>` | > 0 | 直行 / 转弯的编码器计数标定 |
| `E<id> <ppr>` | id = 0/1, ppr > 0 | 设置编码器 PPR（RAM 生效） |
| `SV <deg>` | 输出域绝对角 | 舵机转向角，**直行 = −90**，限位 [−115, −65] |
| `SV+` / `SV-` | — | 在当前角基础上 ±1° |
| `SL/SR/SC <deg>` | — | 左限 / 右限 / 直行位标定（RAM 生效，回显实际生效值） |
| `STEP <id> <u> <t> [div]` | id=0/1, u=±1000, t=100–5000 ms, div=1–4 | 开环阶跃测试（独占控制链，自动发 CSV 遥测） |
| `TEL 0/1` | — | 闭环遥测开关（10 Hz CSV） |
| `FF <val100>` | 0–500 | 速度环前馈系数 ×100（辨识值 ≈ 100，即 1.0） |
| `REC 0/1` | — | 机内记录开关（20 Hz 写 RAM） |
| `DUMP` | — | 重放机内记录 |
| `ODOM 0/1` | — | 里程计上报开关（上行 ODOM/ATT 二进制帧，见 §3.8.1；`STOP` 自动关闭） |
| `WD <ms>` | 0–60000 | 命令看门狗超时（0=关）：超时无 **owner 链路**下行字节 → 自动急停一次并回 `WD TIMEOUT STOP`；随后收到任意字节自动解除闩锁重新武装 |
| `LINK` | — | 查询指挥权 → `OWNER:USB` / `OWNER:UART`（**任意链路直达，不受门控**） |
| `LINK USB` / `LINK UART` | — | 切换指挥权（接管/让出/抢回三语义合一）；调参会话中回 `BUSY:SESSION`；目标链路被编译期关闭回 `LINK:OFF` |
| `ITEL 0/1/2` | — | IMU 姿态遥测（1=CSV 见 §3.5(d)，2=VOFA+ FireWater 7 通道真实物理量；默认 5Hz；`STOP` 自动关闭） |
| `IGAIN <kp100> <ki100>` | ≥0 | Mahony 增益 ×100 在线整定（默认 50 0；`IGAIN 0 0` = 纯陀螺积分） |
| `IDRIFT 0/1` | — | 运行时漂移补偿开关（关 = 完全无补偿的原始陀螺积分，IMU-1 专案 E1 实验） |
| `IRATE <ms>` | 20–1000 | IMU 更新周期（默认 100=10Hz；50 时注意 ITEL 带宽翻倍） |
| `ICAL` | — | 重新触发零偏校准（需车体静止水平，约 5s，完成后 yaw 归零） |

> 手动指令（`M0/M1/MS/B0/B1` 及对应的二进制帧）会**主动退出巡线**（接管权语义），否则 50 ms 后会被巡线状态机覆盖；想恢复巡线发 `L 1`。
>
> **链路门控例外**：`STOP` 与 `LINK` 系列在**任何链路**都有效（安全通道）；其余运动/配置命令只在 **owner 链路**上被受理，非 owner 链路会收到 `BUSY:<owner>`（详见 §3.2.1）。

### 3.8 下行②：二进制帧

适合上位机做"精确参数下发"（浮点值无需文本化）。

```
┌──────┬──────┬─────────────┬─────────┐
│ 0xAA │ CMD  │   参数区…    │ FF FF   │
└──────┴──────┴─────────────┴─────────┘
  帧头   1 字节   按命令定义     帧尾
```

- 多字节浮点用 **IEEE-754 单精度 + 小端**（与 MCU 内存序一致，`memcpy` 直取）
- 帧尾 `FF FF` 结束本帧；**同一帧内允许出现 `0xAA`**（不重新同步）

| CMD | 参数区 | 帧总长 | 含义 | 应答 |
|:---:|--------|:---:|------|------|
| `0x01` | `id`(1) + `float`(4) | 9 | 电机目标转速（带符号 RPM） | `M<id>:<rpm>RPM` |
| `0x02` | `id`(1) + `float`(4) | 9 | 电机线速度（m/s） | `M<id>:<cm/s>cm/s` |
| `0x03` | `id`(1) | 5 | 单轮刹车 | `M<id>:BRAKE` |
| `0x10` | `0x00`(1) + `float`(4) | 9 | 舵机角（输出域绝对角，直行 −90） | `SV:<deg>` |
| `0x20` | `id`(1) + `float`(4) | 9 | **开环占空比**（%，−100~100；会退出巡线） | `D<id>:<pct>.<1位小数>`（如 `D0:50.0`）；越限回 `?` |
| `0xE0` | `id`(1) + `float`×3（kp, ki, kd） | 17 | PID 增益 | `OK` |
| `0xF0` | — | 4 | 心跳 | `PONG` |
| 其他 | — | — | 未识别 | `?` |

**示例（Python，下发 0x01 让 M0 以 60 RPM 转）**：

```python
import struct, serial
ser = serial.Serial("COM14", 9600, timeout=0.2)
frame = bytes([0xAA, 0x01, 0x00]) + struct.pack("<f", 60.0) + b"\xFF\xFF"
ser.write(frame)
print(ser.readline())        # b'M0:60RPM\r\n'
```

**重同步**：若一帧在 **100 ms 内没有收到新字节**（例如蓝牙吞掉了帧尾），固件丢弃半帧并重新寻找 `0xAA`。上位机因此无需为重传做特殊处理，但应保证**一帧字节连续发送**。

### 3.8.1 上行二进制遥测帧（v2，2026-09-14 新增 — 上位机 odometry 数据源）

帧体系与 §3.8 完全一致（`0xAA` 帧头 + CMD + 小端参数区 + `FF FF` 帧尾，**无校验**——
需求方确认"只要增量+时间戳"，坐标漂移由上位机纠正）。`ODOM 1` 开启，`ODOM 0` / `STOP` 关闭。

| CMD | 参数区 | 帧总长 | 频率 | 含义 |
|:---:|--------|:---:|:---:|------|
| `0x51` ODOM | `ΔX`(f32) + `ΔY`(f32) + `Δθ`(f32) + `ts_ms`(u32) | 20 | **20 Hz**（50 ms，与控制环同拍） | 车体系**增量位姿** |
| `0x52` ATT | `roll`(f32) + `pitch`(f32) + `yaw`(f32) + `ts_ms`(u32) | 20 | 10 Hz | 欧拉角透传（IMU Mahony，°） |

**坐标域约定**（解析前必读）：

| 字段 | 单位 | 方向/区间 | 说明 |
|------|------|------|------|
| `ΔX` | mm | 车头正前为正 | 车体系位移增量（**中点积分**：ΔX = Δs·cos(Δθ/2)） |
| `ΔY` | mm | 车体左侧为正 | 同上（ΔY = Δs·sin(Δθ/2)） |
| `Δθ` | ° | 逆时针为正 | 航向增量，归一 (-180, 180]；**主路径 = IMU yaw 差分**（打滑不误），编码器差分仅作回退 |
| `ts_ms` | ms | `HAL_GetTick()` | 下位机毫秒计数，供上位机对齐增量帧 |

**上位机积分示例**（世界系重建轨迹）：`θ += Δθ; x += ΔX·cos(θ−Δθ/2); y += ΔY·sin(θ−Δθ/2)`（角度转弧度）。

**带宽与阻塞注意**：走 **USB 主链**时无实际约束（实测 20 Hz ODOM + 10 Hz ATT 连续 10 s 零丢帧、控制环 20 Hz 不漂移），这也是 ROS 下位机模式下 ODOM 的首选链路。走 **BT04 备链**时两帧全开 ≈ 600 B/s（62%@9600）且为**阻塞发送**（每帧 ~21 ms@9600）——仅对接/调试会话开启；要跑 50 Hz（20 ms 周期）或与其它遥测并行，**必须先把链路提速到 115200**（固件 `huart2.Init.BaudRate` 与对端同步改）。数据来源标定：PPR=1466（实测）、轮周长 205 mm（README §1）、轮距未参与（IMU yaw 模式）。

### 3.9 节拍与带宽预算

| 环节 | 周期 | 说明 |
|------|------|------|
| 命令解析 | 事件驱动（主循环） | 中断收字节 → ringbuf → 主循环清空解析，无轮询丢字节 |
| 速度环控制 | 50 ms | 测速 → PID + 前馈 → 下发 |
| 显示 / 传感器 | 100 ms | OLED 单页轮转（8 页 800 ms 一轮） |
| 阶跃遥测 | 50 ms（20 Hz）或 100 ms（10 Hz） | |
| 闭环遥测 | 100 ms（10 Hz） | |
| 机内记录 | 50 ms（20 Hz），128 条缓冲 | |
| IMU 遥测 `ITEL 1` | 200 ms（5 Hz，随 IRATE 变） | |

**9600 bps = 960 B/s** 的预算（**仅 BT04 备链受限**；USB 主链不受此约束，行字节数按实测数据/格式计算，含 `\r\n`）：

| 遥测 | 单行字节 | 速率 | 占用带宽 |
|------|:---:|------|---------|
| 闭环 `TEL 1` | **18–19 B**（`600000,30,31,0,0`；开跑 1 小时后 tick 变长 +1 B） | 10 Hz | **180–190 B/s（≈20%）** ✅ |
| 阶跃 20 Hz（`div=1`，默认） | **12–15 B**（实测均值 14.8 B） | 20 Hz | ≈ 296 B/s（31%）⚠️ 实测系统性丢行 |
| 阶跃 10 Hz（`div=2`） | 同左 | 10 Hz | ≈ 148 B/s（15%）✅ 推荐 |
| ODOM 20 Hz + ATT 10 Hz（§3.8.1） | 20 B/帧 | — | ≈ 600 B/s（62%）⚠️ 阻塞发送；提速 115200 后仅 5% |

> ⚠️ 蓝牙链路的实际瓶颈不是带宽而是 **BT04 模块的打包/投递节拍（实测 ≈ 15.5 ms）**，
> 表现为"命令往返延迟量化到 15.5 ms 的整数倍"，且**高行速率下会成块丢行**。
> 丢行应对：① 遥测降频（`STEP … 2`）② 用 `REC` + `DUMP` 机上记录后慢速重放。

### 3.10 上位机对接建议

最小可用流程：

1. 打开串口（**USB 主链**：打开即算活；**BT04 备链**：复位后读到 `UART2 Ready` 才算链路 OK）
2. 发 `PING`，收到 `PONG` 即固件运行正常
3. 要控车：先确认指挥权（`LINK ?` → `OWNER:`；不是自己就发 `LINK USB` / `LINK UART` 取回），
   再发 `M0 <rpm>` / `M1 <rpm>`（或二进制帧）——**读到对应 `M0:…RPM` 才算执行**（否则可能收到 `BUSY:<owner>`）
4. 要调参：`TEL 1` → 发目标 → 按 CSV 收数据 → `TEL 0` 关闭
5. 任何时候发 `STOP` 急停（会自动关巡线 / 关遥测 / 舵机回正；**不受指挥权门控**）

仓库 `tools/` 已提供现成的 Python 脚本（无第三方依赖，仅需 `pyserial`）：

| 脚本 | 用途 |
|------|------|
| `link_probe.py` | **双链路统一探测**：扫口 + 归类（USB CDC / BT04 / 其它蓝牙）+ 逐口隔离 `PING` 探测 + 报 owner + 结果存档（`tools/data/link_probe.txt`）；`--wait` 轮询等连接、`--pair` 配对引导、`--echo` USB 回显用例（需 `USB_ECHO_TEST` 固件） |
| `bt_connect.py` | BT04 连接助手（**兼容壳**，实现已并入 `link_probe.py`，等价 `link_probe.py --wait <秒> --pair`）；发现后写 `tools/data/bt_port.txt` 供其它脚本使用 |
| `link_regress.py` | **双链路真机回归**（`doc/双链路仲裁设计文档.md` §8 常跑项）：A 段链路体检（PING / ITEL / ODOM 20Hz / 突发零丢）+ T1/T2/T5/T7（双链路应答、owner 三语义、`BUSY` 门控、备链 STOP）；**自动取指挥权并在收尾还原**（避免"命令被 BUSY 拒绝"被误读成故障）。`--usb-only` 可只跑 A 段（当前 13/13 PASS） |
| `flash_flow.py` | 烧录流程自动化：`--flash` 编译+烧录+提示拔插 USB+**自动等端口重现**+`PING` 验证+报 owner；`--verify` 事后复核 |
| `bt_cmd_test.py` | 交互式命令台 / 自动回归（`--ping` / `--auto` / `--bin`） |
| `step_capture.py` | 采集阶跃 CSV → `tools/data/*.csv` |
| `step_ident.py` | FOPDT 模型辨识 + SIMC 参数建议 |
| `ab_step.py` | 参数 A/B 对照实验与量化指标 |
| `tune_smoke.py` | 调参链路冒烟测试 |
| `imu_capture.py` | IMU 遥测采集（配合 `ITEL`） |
| `imu_sim_verify.py` | imu_filter 算法 PC 仿真一致性验证 |
| `imu_turn_test.py` | 90° 转角协议化测试（跟随角/回落量/静置漂移） |
| `car_cfg_matrix.sh` | `car_config.h` **链路开关四组合编译矩阵**（含双 0 被拒校验 + Flash/RAM 记录） |

### 3.11 已知限制与注意事项

| 限制 | 影响 | 应对 |
|------|------|------|
| **默认无周期上报** | 不上报不等于死机 | 按 §3.5 打开遥测；或看 OLED |
| 无 CRC 校验 | 帧内容错误无法察觉 | 低风险（`FF FF` 截帧概率极低）；待办项 |
| 帧尾 `FF FF` 若出现在参数区会提前截帧 | 参数被截断 | 当前 float 参数实际不会产生；100 ms 超时自动重同步 |
| `ack()` 为**阻塞发送** | 9600 下 6–11 ms/次；`DUMP` 逐行 20 ms 阻塞主循环 | 已限流使用；后续改中断/DMA + 发送队列 |
| 遥测为行文本（非二进制） | 带宽利用率低 | 原 `firewater_send` 二进制帧已删除（2026-09-14）；VOFA+ 波形走 `ITEL 2`；更高带宽需先扩协议/提速串口 |
| 蓝牙端口号随配对变化 | 脚本硬编码端口会失效 | 用 `link_probe.py` 扫口并写 `tools/data/bt_port.txt`（`bt_connect.py` 为兼容壳） |
| **USB 软复位后不重枚举** | 烧录后打开端口报错 31，像是"板子死了" | 拔插一次 USB；或直接用 `tools/flash_flow.py --flash`（自动等端口重现 + PING 验证）。设备侧无法造断开事件（DP 上拉为外部固定），根治需改硬件 |
| **非 owner 链路的命令被拒** | 同一命令在另一条链路上回 `BUSY:<owner>` | 先 `LINK ?` 查 owner，必要时 `LINK USB` / `LINK UART` 切换；`STOP` 不受限制 |
| **单链路编译模式** | 某一链路被 `car_config.h` 编译期关闭后，该端口**没有任何应答**（不是故障） | `LINK` 请求会明确回 `LINK:OFF`；确认真值源是 `car_config.h` 的 `CAR_FEATURE_USB` / `CAR_FEATURE_UART`（两宏不可同时为 0，CMake 会拒绝） |
| **单次突发下行 ≤ 239 B**（≈47 条文本命令；二进制帧仍应"一帧连续发"） | 超限**丢新字节**（已收数据不受影响） | 突发之间留一拍处理时间；溢出计数可查（OLED 页 7 `O<n>` 字段）。容量不可再扩：head/tail 为 `uint8_t`，上限 255（2026-09-19 实测 30/40 条零丢、60 条(300B) 超限） |
| 角度应答仅一位小数 | 不能当高精度读数 | 精度需求高时用二进制帧/机上记录 |
| `M0 60` 这类手动命令会退出巡线 | 按键后巡线停 | 设计如此（接管权语义）；恢复巡线发 `L 1` |
